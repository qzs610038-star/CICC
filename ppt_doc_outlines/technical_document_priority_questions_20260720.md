# 技术文档优先回答问题清单（从《细节问题总清单》中筛选）

> 来源：
> - 问题文档：`technical_document_detail_questions.md`（共 320 题，A–W 共 23 个分组）
> - 技术文档：`technical_document_outline_v2.md`（大纲 V5，已冻结大量口径）
> - 仓库事实基线：`CURRENT_STATE.md`（2026-07-19 单摄接口冻结状态）
>
> 筛选目的：在无法一次回答全部 320 题时，先集中回答「最值得优先回答」的一批。判断标准有三条：
> 1. **真正悬而未决**：大纲 V5 和 CURRENT_STATE 尚未把答案写死，回答后能改变文档结论或系统能否提交。
> 2. **高影响**：回答错会直接导致漏抓官方目标、越级声明板级闭环、或盲审泄密——任一都会扣分甚至废卷。
> 3. **只能靠人确认**：标 `[用户]` 的事实 Codex 无法从源码核实，拖越久越阻塞文档定稿。
>
> 使用方式：每题下方留有「答：」，直接填写即可。不知道时写"不知道/未测试/请Codex查源码"，不要猜测。
>
> 已被大纲 V5 写死、或 Codex 可从源码自动核实的问题，不在本批优先清单中（见文末「已可跳过 / 交给 Codex 自动核实」）。

## 第一优先级：决定「能否正确提交、会不会漏抓官方目标」

这 4 题是整份文档最大的事实风险点。大纲 V5 第 3.2.2 节和第 11.1 节都已明确挂起：任务三、四「颜色也必须匹配」是**团队主动加严**的口径，0715 修正版正文只明确「正方体 + 尺寸关系」，并未显式要求颜色。如果团队理解与现场口径不一致，系统会**漏抓官方尺寸目标**或**多抓非目标物**，直接影响任务三、四得分。

**Q1　P0 [用户]** 官方封面的"报告类型"最终写"技术报告"还是"设计报告"？

答：

> 说明：封面是评委第一眼看到的内容，大纲 V5 自己也只写"暂填技术报告，以官方最终提交口径为准"——属于显式未决。建议与 Q6（是否同时交 PDF）、Q7（截止时间/平台）、Q8（0715 是否最终版）一起由团队对照官方模板原件敲定，不能由 Codex 猜。
