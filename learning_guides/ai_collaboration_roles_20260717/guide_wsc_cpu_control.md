> 生成日期：2026-07-17
> 面向角色：wsc / `@wsc6090-CPU`
> 预计阅读时间：10–15 分钟
> 责任边界来源：[BRANCH_MERGE_GOVERNANCE.md](file:///D:/第十届集创赛-雄芯院材料/docs/merge_governance/BRANCH_MERGE_GOVERNANCE.md#L68-L92)

## 先理解你的接口责任

你的代码不是“收到一堆数然后输出一个颜色”这么简单。板上 CPU 要负责五色、三形状、三尺寸分类，四任务关系判断，逐轮“识别—判断—执行”状态机，结果语义、参数和后续控制；但它不能凭空发明 FPGA 地址，也不能把 Host 测试当成板级闭环。

把 CPU 想象成裁判：FPGA 提交的是带单位和有效位的证据，CPU 依据当前任务规则作出“目标/非目标”和理由，OSD 显示语义，机械臂只有在所有安全门通过时才获得执行请求。裁判不能把一张模拟练习卷当现场计分结果。

## 1. 你必须补齐的知识

### 第一优先级：C 代码与状态机

掌握结构体、枚举、指针、边界检查、整数宽度、`const`/`volatile`、函数返回码，以及状态机的四件事：当前状态、触发事件、动作、副作用和下一状态。重点检查：重复事件是否会重复动作、超时是否能退出、失败是否锁存、下一轮是否被旧数据污染。

### 第二优先级：ABI、MMIO、APB 的关系

- **语义契约**说“字段代表什么、单位是什么、何时有效”；
- **寄存器映射**说“硬件窗口如何组织”；
- **ABI**说“CPU 编译出来的程序如何按约定访问真实硬件”；
- **MMIO**是把读写内存地址变成硬件寄存器访问；
- **APB**是硬件侧低复杂度寄存器总线。

当前 `register_map.md` 明确是候选契约，且地址和生成物必须回到同一批次 `soc.h`/硬件证据；不能因为文档里出现候选基址就直接试探访问，见 [register_map.md](file:///D:/第十届集创赛-雄芯院材料/final_project/integration/register_map.md#L1-L70) 和 [CURRENT_STATE.md](file:///D:/第十届集创赛-雄芯院材料/CURRENT_STATE.md#L33-L59)。

### 第三优先级：构建与证据边界

要能看懂 compile-only、链接、ELF LOAD/entry、QEMU/Host、真实 UART 和 APB 实读分别证明什么。当前 G2 的 C/Python 计数只证明离线负例、顺序和 ACK 校验，不证明 RISC-V 固件、真实 MMIO、板级目标输入或动作闭环，见 [CURRENT_STATE.md](file:///D:/第十届集创赛-雄芯院材料/CURRENT_STATE.md#L26-L31)。

## 2. 你应该怎样使用 Agent

### 用法 A：先让 Agent 画“数据合同”，不要直接接线

```text
只读检查 CPU 输入输出。
请列出每个字段：来源、类型、单位、有效位、更新时间、无效时行为、消费者。
请把候选地址、真实生成物地址、未定地址分开。
不要修改 C、RTL、XML 或 soc.h。
```

如果回答无法指出“输入是什么、输出是什么、谁消费、如何验证”，就还不到实施阶段。

### 用法 B：把真实接入拆成最小阶梯

推荐让 Agent 依次生成实验计划，而不是一次接入全视觉：

1. 固定 CPU Hello：证明当前 ELF 能运行到 UART0。
2. 固定硬件 MAGIC/只读寄存器：证明 CPU→APB 的一条最小路径。
3. 单个视频快照字段：先打印 `valid/area/x/y` 等已定语义。
4. 分类器替换输入：确认真实快照和 Host 输入具有相同单位与边界。
5. CPU 结果语义交给 OSD/后续控制。

每一级都保存原始串口输出和失败日志。上一级未通过时，不要让 Agent“顺手继续接下一级”。

### 用法 C：代码修改必须锁定文件区

```text
目标 Gate：……
允许修改：CPU 源文件 / 测试文件 / 明确指定的构建入口
禁止修改：FPGA XML、peri.xml、SDC、顶层、正式地址、机械臂动作
要求：保留现有 Host 测试，新增一个可复现负例，并报告编译、链接和运行时边界。
```

### 用法 D：让第二个 Agent 专门找“假通过”

```text
只审查，不修改。
请找出这份结果中哪些只是 compile-only、Host/mock 或静态推断。
逐项列出真正还需的板级证据，并检查是否存在重复动作、旧数据、超时死循环和未知地址访问。
```

## 3. 你与队友的交付关系

交给 qzs：

- CPU 读取的字段和状态机输入契约；
- 当前依赖的硬件批次、`soc.h`/ELF 身份、构建命令；
- Host 通过项、板级未验证项、需要上板观察的具体串口文本。

向 libaoxun 索取：

- 与当前 bitstream 同批的寄存器/快照语义；
- 时钟域、快照锁存、有效位和清除/提交规则；
- 不要只要“地址”，还要要“字段单位、更新时间和失败时值”。

如果硬件 ABI 尚未定版，你的正确动作是把 transport 保持 fail-closed，并在报告中写明“等待硬件事实”，而不是用历史占位地址把代码接上。

## 4. CPU 合并验收清单

- [ ] 分类器、任务 matcher、round controller 的输入输出和理由码有明确契约。
- [ ] 单元/Host 测试覆盖无效输入、边界、重复事件、超时、错误锁存。
- [ ] 代码没有用未知 MMIO 地址试探硬件。
- [ ] `volatile`、整数宽度、符号转换和时间回绕处理有解释。
- [ ] 构建矩阵区分 compile、link、ELF 审计、Host/QEMU、板上运行。
- [ ] 每次硬件输入变化都标记旧 ELF/板测证据失效。
- [ ] 未通过板级 Gate 时，机械臂命令保持禁用或明确降级为 SKIP。
