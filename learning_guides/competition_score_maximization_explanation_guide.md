## 🔍 专业术语与“黑话”大白话翻译

方案里提到了很多高大上的学术词汇，我们用生活中的场景来给它们“脱掉外套”：

| 方案原文术语 | 严密工程定义 | 🚴 大白话/生动比喻解释 |
| :--- | :--- | :--- |
| **P0 主线 (Priority 0)** | 最高优先级任务，完不成它，整个项目等于零。 | 🎮 **通关游戏里的“主线任务”**：不打通就无法通关。其他次要功能（如美化界面、极限加速）是“支线任务”，有空再做。 |
| **PNR (Place and Route)** | 布局布线。将写好的电路蓝图塞进 FPGA 芯片内部，并合理连线。 | 🏢 **在寸土寸金的市区建大楼并修路**：把各种逻辑门分配到芯片的具体物理位置上，并把它们用导线连起来。如果大楼太多或者路太堵，就会“PNR 失败”（修不通了）。 |
| **VDB 与 Debugger** | FPGA 的调试数据库文件。用于在上板运行时观察内部信号。 | 📹 **大楼里的“监控摄像头”**：如果出了 Bug 却看不到内部波形，我们就是瞎子。拥有 `.dbg.vdb` 才能在电脑上“看监控”诊断案发现场。 |
| **OSD (On-Screen Display)** | 在视频显示画面上叠加字符和图形的技术。 | 📺 **看视频时的“弹幕”和“内嵌字幕”**：摄像头拍到的画面是背景，OSD 负责在上面写字（比如显示当前是任务几、识别到了什么颜色）。 |
| **APB 总线 (Advanced Peripheral Bus)** | 处理器与外设之间传输数据的一种低速总线。 | ✉️ **大楼里的“公文传递员”**：CPU 算出了分类结果，通过 APB 总线把公文塞给 FPGA 负责画画的 OSD 模块。 |
| **CDC (Clock Domain Crossing)** | 跨时钟域。信号从一个时钟速度传输到另一个不同时钟速度的区域。 | 📞 **“隔洋通话”**：两人时差不同，一个人说话太快，另一个人容易漏听，需要“打两拍”（双锁存器）或握手来确保对齐，防止信号“摔倒”（亚稳态）。 |
| **Debayer 字节序** | 摄像头拍出来的原始图像数据（RAW）转换成彩色图像（RGB）的解码规则。 | 📖 **“译电员的密码本顺序”**：如果字节顺序错了一位，译出来的电报就全是乱码——在屏幕上就会出现“红花变绿叶”、“人脸变蓝脸”的诡异现象。 |
| **Mock 模式 (模拟测试)** | 用软件虚拟一个假的硬件设备，来测试系统逻辑是否跑得通。 | ✈️ **“飞行模拟器”**：在不上真机、不碰昂贵机械臂的前提下，先用模拟器测试我们的决策状态机，防止由于逻辑混乱导致机械臂“坠机砸盘”。 |
| **Latch (锁存) 与防抖** | 保持状态不随外界抖动而变。 | 🚪 **“门上的插销”**：在摆放物体时，手可能会晃动。我们等画面静止后插上“插销”（锁存），之后手再怎么晃，识别结果也锁死了，不会乱变。 |
| **到位振荡 (Oscillation)** | 机械臂高速移动到目标点时，由于惯性而在终点附近产生来回摆动的物理现象。 | 🚗 **“坐车猛刹车”**：司机一脚踩死，车身会前后晃动。我们必须等车身彻底静止（连续确认到位），机械臂才能闭合夹爪，否则会一爪子把目标推飞。 |
| **非阻塞轮询 (Non-blocking)** | 状态机等待硬件信号时，加入超时限制并允许执行其他事务，避免死循环阻塞。 | 📱 **“留号排队”**：不用在柜台前死等，留下电话（设置超时计数器），柜台好了打给你，在此期间你可以干别的。 |

## 🏗️ 三大核心架构决策的底层逻辑

为了让你能够看懂为什么方案要做这些“看似绕弯子”的决定，这里把决策背后的底层逻辑拆解给你看：

### 决策一：为什么不先调机械臂，而是先把“CPU得分引擎”和“FPGA生产构建”设为双 P0？
* **比赛残酷的积分规则**：
  官方规定单轮评分按：**识别 25% $\rightarrow$ 判断 25% $\rightarrow$ 执行（机械臂）50%** 串行计算。这意味着，**如果识别错了，后面机械臂抓得再准，本轮也是 0 分**！
* **战术破局点：无机械臂得分闭环 (SKIP 拿低风险分)**：
  在 20 轮演示中，有 **13 轮是非目标轮**。对于非目标轮，系统不需要去抓，只需要**“正确识别 + 正确判断 + 明确说我不抓（SKIP）”**，就能直接拿走这一轮的全部执行分！
  如果我们先把 CPU 的任务分类判断逻辑做完美（也就是“CPU得分引擎”），配合 FPGA 稳定的画面输出，**即使我们完全禁用机械臂，理论上也能稳拿 54 分/65 分（也就是 83.1% 的分数）**！
  所以，我们要先把这 83% 的保底分数抓在手里，再让机械臂用**一套最简单的抓放路径**覆盖那 7 个目标轮，从而冲刺满分。

### 决策二：为什么要写一个独立的“一轮一事务控制器 (`round_controller`)”？
* **乱套的视频帧**：
  摄像头一秒钟会传进来 30 帧画面。如果直接在 [main.c](file:///d:/第十届集创赛-雄芯院材料/final_project/cpu/app/src/main.c) 里判断：看到红正方体就让机械臂去抓，那么在 1秒钟内，CPU 会向机械臂发送 30 次“去抓！”的指令。机械臂会当场因为通信堵塞而“抽搐”甚至死机。
* **地铁安检闸机的状态机设计**：
  我们引入了 [round_controller.c](file:///d:/第十届集创赛-雄芯院材料/final_project/cpu/app/src/round_controller.c)，它像地铁安检机一样，有一套严格的生命周期：
  ```
  【配置任务】 ➔ 【等待摆放】 ➔ 【画面消抖/静止】 ➔ 【锁存识别结果】 ➔ 【决定抓还是跳过】 ➔ 【等待机械臂抓完】 ➔ 【确认拿走物体】 ➔ 【回下一轮】
  ```
  **同一物体只锁存一次识别结果，同一轮最多只发送一次抓取请求**。在这个生命周期结束前，哪怕视频画面里手晃了、画面闪烁了，状态机也绝不会重复触发，极其安全。

### 决策三：视觉标定为什么要“物理治具优先”？
* **别用算法解决能用物理解决的问题**：
  如果相机是手持的，高度变了 1 厘米，正方体投影在画面里的像素大小就会变，算法里的尺寸判断就会出错。如果现场光线一会儿亮一会儿暗，颜色识别就会乱套。
* **战术**：
  **“拍照用脚架，演戏进影棚”**。我们建议制作一个一体化底板，把相机高度、角度、补光灯、物体的摆放区域、机械臂的底座死死固定在一起。用遮光罩挡住现场展馆忽明忽暗的强光。环境固定了，算法的分类准确率瞬间能从 50% 提升到 99%。

## 🛠️ 首个可验证 Checkpoint（我们下一步怎么干？）

为了不引入任何硬件损坏风险，我们为你设计的**第一步（Checkpoint）**是完全在**软件/电脑模拟环境**中进行的。在这一步，我们不烧录 FPGA，不给机械臂通电。

我们要完成的目标是：
1. **写出真值表**：把官方 4 个任务、20 轮所有可能的输入情况（比如：看到蓝正方体，参考是 2cm，在任务三下，判断结果应该是什么）全部列成一张真值表。
2. **定好 API 契约**：在 [task_matcher.h](file:///d:/第十届集创赛-雄芯院材料/final_project/cpu/app/include/task_matcher.h) 里定义好新版数据结构（即 `competition_target_t`）以及它的判断函数。
3. **编写防抖与锁存测试**：在 [test_round_controller.c](file:///d:/第十届集创赛-雄芯院材料/final_project/cpu/tests/test_round_controller.c) 中测试：当我们连续给状态机发送 100 个忽变忽常的视频帧时，它是否能稳稳地只触发一次动作。

## 😈 红蓝对抗：方案关键决策的“隐形地雷”（Red Team Analysis）

作为对该方案的对抗性审查，我们在表面“稳健”的背后，扒出了这些决策可能引发的致命连带风险。在做出上述决策前，请务必掂量这些“雷”：

### 💣 风险一：“先保底，后动手”可能沦为“纸上谈兵”
* **决策点**：双 P0 并行（CPU判断优先，机械臂延后，即 Gate C 到 Gate D 的延迟）。
* **隐形地雷**：如果我们在比赛前几天才发现真实的机械臂因为桌子平整度、电源干扰或者串口信号衰减而**完全无法准确走到坐标点**，我们将没有时间修改底层动作控制策略。
* **致命推演**：CPU 虽然满分通过了识别和判断，但在评委眼里，一个“疯狂对着空气乱报结果，但手一动不动或者一动就砸盘”的机器，可能会被主观判定为“未完成基本闭环”，从而在执行分和印象分上遭遇大溃败。

### 💣 风险二：“完美状态机”可能变成“死锁囚笼”
* **决策点**：独立的 `round_controller` 安检机式状态机。
* **隐形地雷**：状态机越严密，越容易因为一个异常信号的丢失而“卡死”。
* **致命推演**：如果负责检测“物体已拿走”的状态或确认按键稍微抖了一下导致漏判，状态机就会死等。在现场 10 分钟限时里，操作员如果不具备随时“强制清空（Reset）”或介入跳过的能力，系统可能会在第 3 轮直接死锁，导致后续 17 轮全部超时 0 分。

### 💣 风险三：16/32 位通信契约带来的“蝴蝶效应”
* **决策点**：将目标配置从 5 位升级为 16/32 位。
* **隐形地雷**：这不是单纯改几行 C 代码。它意味着 FPGA 和 CPU 之间的 APB 总线位宽需要对齐，甚至可能动到 `top.v` 里的引脚映射和跨时钟域（CDC）逻辑。
* **致命推演**：原本勉强能过的 PNR（布局布线）可能会因为总线加宽而导致拥堵，暴露出新的时序违例（Timing Violation）。原本还能勉强输出的视频，可能因为修改了硬件契约而彻底黑屏。

### 💣 风险四：“一条路径通吃”的物理天真
* **决策点**：只用一条固定动作抓取所有（20/25/30mm）正方体。
* **隐形地雷**：机械臂的夹爪在夹持 20mm 和 30mm 正方体时，其中心点高度和下压极限在物理上是不同的。
* **致命推演**：为了能抓起 20mm，夹爪可能被设置得过低，导致在抓 30mm 时狠狠撞击桌面；或者反之，抓 30mm 刚好，但在抓 20mm 时像是在“摸头”，夹不稳导致半空掉落。比赛规则中，**任何提前释放或轻微碰撞直接按跌落（失败）处理**。

### 💣 风险五：过度依赖物理治具的“温室综合症”
* **决策点**：固定相机、高度、遮光罩（物理治具优先）。
* **隐形地雷**：我们预设现场允许部署这些庞大的自制外设。
* **致命推演**：如果现场评委以“不符合实际工程应用要求”或“超出桌面分配尺寸限制”为由，强令拆除遮光罩或移动底板。失去了物理治具的庇护，未经受过恶劣环境训练的单薄算法将瞬间崩溃，识别准确率将从 99% 直接暴跌到随机盲猜。
