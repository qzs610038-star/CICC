## 1. 今日最核心的改动与经验

### 📌 核心点一：三方合并靠固定 SHA，不靠“最新分支”口头描述

* **改动背景与问题**：本次分别固定 WSC `cbe6eaf`、QZS PR #12 `b3682a4`、libaoxun PR #13 `5bada18`，并建立独立来源提交。
* **源码剖析**：[SESSION_HANDOFF](file:///D:/第十届集创赛-雄芯院材料/SESSION_HANDOFF.md#L5-L12) 保存来源与本地合并提交；WSC 根目录重复指南被排除，只保留规范目录版本。
* **经验总结**：这像三辆货车分别过磅、贴封签，再进入总仓；不能把三车货倒成一堆后才猜来源。

### 📌 核心点二：失败和未运行必须进入交接，而不是藏在口头说明里

* **改动背景与问题**：用户要求停止继续检测，因此 classifier `FAIL` 和未运行门禁必须成为仓库事实。
* **源码剖析**：[测试状态表](file:///D:/第十届集创赛-雄芯院材料/CURRENT_STATE.md#L27-L43) 区分 `PASS/FAIL/NOT RUN`；[handoff](file:///D:/第十届集创赛-雄芯院材料/SESSION_HANDOFF.md#L24-L34) 明确下一执行者不能继承旧数字。
* **经验总结**：工程交接像医院病历：没检查的项目写“未检查”，异常写“异常”，不能为了让表格好看而补成“正常”。

## 2. 可迁移的系统级工程经验

* **避坑警示**：本结果仍在独立本地分支，`main` 未改、远端未推送。队友不能在 PR #12/#13 旧分支上直接 `git pull` 获取它。
* **通用方法论**：先由队友本地决定接口文件、所有权和任务分工，再进入实现；机械臂、UART2/J52 和真实硬件动作继续隔离。

## 3. 推荐自行学习的相关知识

* **优先赛方资料**：阅读官方比赛细则和仓库 Review Packet 模板，理解哪些证据能证明识别、判断、执行三个不同层次。
* **拓展基础知识**：学习 Git 固定 SHA 审查、选择性 merge 和可追溯提交。把它理解为供应链批次管理：每个来源、舍弃项和验收结果都必须能回查。
