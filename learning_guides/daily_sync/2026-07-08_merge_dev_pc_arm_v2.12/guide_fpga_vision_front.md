## 1. 今日最核心的改动与经验

今天合并的 `mycobot_pc_tests` v2.10~v2.12 改动链中，虽然主要是 PC 控制端的软件更新，但它展示了一个极为精妙的系统设计原则——**“底层物理特征提取”与“上层业务逻辑”的解耦**。这直接规范了我们 FPGA 视频前端与 CPU 之间的数据交换契约。

### 📌 核心点一: 底层有效性校验与业务安全决策的完全剥离
* **直观比喻（地铁安检模型）**：
  就像坐地铁，“安检”只管行李里有没有易燃易爆品（只负责底层数据合法性）；而“闸机”只管你卡里有没有钱、允不允许进站（负责业务决策）。
  如果安检人员越权，去检查你卡里有没有钱，没钱就不让你放行李，这就叫**“逻辑耦合”**。在机械臂控制中，如果我们把“抓取高度不能超限”的安全阈值硬塞进底层串口驱动，那么在机械臂“直立回零”的正常路径中（直立高度通常很大），底层就会把这部分正常的数据当成非法越界丢弃，导致通信异常假死。
* **源码剖析**：
  在 [teach_replay_pick_return_ready.py:L594-L616](file:///d:/第十届集创赛-雄芯院材料/mycobot_pc_tests/teach_replay_pick_return_ready.py#L594-L616) 中，校验机制被清晰拆分：
  1. **底层物理保真 (`is_valid_coord_reading`)**：只根据传感器的量程限制判断数据是否合法（如 $X, Y \le 500\text{ mm}$，$-100 \le Z \le 500\text{ mm}$）。
  2. **上层业务门控 (`is_safe_coord`)**：只在执行 `pick/drop` 动作时判定坐标是否安全（如抓取时要求 $Z \le 280\text{ mm}$，防止撞击）。
* **经验总结**：
  物理层只管数据“真不真”（保真度），业务层只管数据“对不对”（安全限制）。

## 2. 可迁移的系统级工程经验

* **避坑警示**：
  在 FPGA 特征统计输出（如 ROI 像素面积、长宽比、HSV 统计值）中，**禁止在 RTL 逻辑中硬编码特定的颜色分类或判定阈值**。例如，不要因为“这次只抓红色物块”，就直接在 RTL 级把非红色像素的面积丢弃。一旦现场光照或物块颜色微调，我们就必须重新综合编译 FPGA 工程，极其低效。
* **通用方法论**：
  **计算归硬件，决策归软件**。FPGA 负责执行高保真、低延迟的特征提取，只管把提炼出的 ROI 特征准确映射到 APB 寄存器上；至于这到底是什么颜色、是否满足抓取逻辑，全部交由 CPU 侧的参数分类表去柔性判定。

## 3. 推荐自行学习的相关知识

* **优先赛方资料**：
  * **推荐学习内容**：查阅仓库内 `EDA软件培训文档及视频/` 中的 **“Efinity APB 总线与 GPIO 端口映射配置指南”**。
  * **应用与意义**：重点掌握 FPGA 侧如何将提炼的特征通过 APB 寄存器总线与 B 侧 CPU 建立整齐的映射地址，保证双端的数据对齐。

* **拓展基础知识**：
  * **推荐学习内容**：**CDC（跨时钟域）数据打拍与消抖逻辑**
  * **应用与意义**：输入电平与串口信号容易产生毛刺，自学双锁存器打拍与 CDC 握手协议，给 CPU 寄存器提供最稳定、不含毛刺的特征源。
