## 1. 今日最核心的改动与经验

### 📌 核心点一：合并的不只是代码，还有“不许做什么”的证据

* **改动背景与问题**：PC 路线完成 5/5 不代表板上 CPU、UART2 或比赛抓放闭环。若合并时只保留成功日志，很容易丢失 drop_hover 软通过、夹爪无反馈和外部几何未验收等关键限制。
* **源码剖析**：[CURRENT_STATE.md](file:///D:/第十届集创赛-雄芯院材料/CURRENT_STATE.md#L41-L53) 并列保留 `PASS_WITH_RISKS`、E3 `NOT_VERIFIED` 与真实动作 NO-GO；[真机调试记录](file:///D:/第十届集创赛-雄芯院材料/debug_records/mycobot_route_a_experiment_debug_record_20260714.md#L1-L20) 使用仓库相对链接，不再绑定个人 D 盘 URI。
* **经验总结**：安全记录像降落伞的检查签，不是“项目附件”。代码合并成功只说明背包拉链合上了，不能把伞布是否完好这条记录扔掉。

### 📌 核心点二：CURRENT_STATE 冲突必须语义合并

* **改动背景与问题**：CPU 分支记录编译门，myCobot 分支记录真机风险；Git 无法判断哪段更重要，自动选择任一侧都会制造状态失真。
* **源码剖析**：[CURRENT_STATE.md](file:///D:/第十届集创赛-雄芯院材料/CURRENT_STATE.md#L30-L53) 先列最新 CPU 集成门，再保留前一日 myCobot 证据，并明确二者共同不放行 G4/真实动作。
* **经验总结**：这像医院交班：化验结果和护理风险不是互斥答案，必须同时写进病历；“冲突已解决”不等于“选了一边”。

### 📌 核心点三：软到位只能作为风险受控的候选路径

* **改动背景与问题**：5/5 `drop_hover` 依靠约 2.02°软容差通过，夹爪动作缺少位置/停止闭环。
* **源码剖析**：[180°评价记录](file:///D:/第十届集创赛-雄芯院材料/final_project/docs/review_packets/mycobot_180deg_initial_verification_evaluation_20260714.md#L1-L80) 将其判定为 `PASS_WITH_RISKS`，而不是比赛验收 PASS。
* **经验总结**：“软到位”像投篮擦框入网，可以让开发流程继续，但比赛前仍要确认篮筐位置、球是否抓稳以及底座是否会晃。

## 2. 可迁移的系统级工程经验

* **避坑警示**：不得把 PC `pymycobot` 路线写成正式闭环；不得因 CPU Host/ELF PASS 提前接 J52；不得在合并冲突中删除 NO-GO、失效条件或未验证项。
* **通用方法论**：版本集成采用“功能代码 + 风险证据 + 验收命令 + 失效条件”四件套。任何结论都要能回答：在哪个 commit、哪个环境、通过了哪一门、下一门是谁负责。

## 3. 推荐自行学习的相关知识

* **优先赛方资料**：
  * **推荐学习内容**：myCobot 串口协议、开发板 J52/UART2 管脚材料和官方比赛 180°±10°/最大臂展要求。

* **拓展基础知识**：
  * **推荐学习内容**：安全状态机、有限重试、失效条件管理和 Git 语义冲突复核。
  * **应用与意义**：把“保险丝复位”式有限重试与物理断电红线结合，避免软件容错演变成无限动作。
