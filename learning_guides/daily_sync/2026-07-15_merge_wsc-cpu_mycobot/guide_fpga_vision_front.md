## 1. 今日最核心的改动与经验

### 📌 核心点一：CPU 语义层接入，不等于新增 OSD/APB 协议

* **改动背景与问题**：wsc 新增了统一的识别、判断、执行和理由语义，但这些结构明确是 CPU 内部类型，不能直接把结构体字节写进 FPGA 寄存器。
* **源码剖析**：[main.c](file:///D:/第十届集创赛-雄芯院材料/final_project/cpu/app/src/main.c#L383-L403) 现在先将 `round_controller_output` 投影为 `cpu_display_result_t`，矛盾组合会 fail closed；这里没有新增 APB 地址、位宽或 CDC 连线。
* **经验总结**：这像“先统一快递单上的中文品名，再设计传送带条码”。CPU 先把语义说清楚，FPGA 端的寄存器编码和 OSD 像素渲染仍须另立契约，不能把内存布局当硬件协议。

### 📌 核心点二：adapter 已能构建，不代表硬件事件链已接通

* **改动背景与问题**：wsc 旧版 main 使用 UART 单字符事件和直接 CLINT 时基，但当前 G0–G3 尚无受审事件源与正式单调时基。
* **源码剖析**：[CURRENT_STATE.md](file:///D:/第十届集创赛-雄芯院材料/CURRENT_STATE.md#L30-L39) 明确：`main_loop_adapter.c` 已进入目标构建，正式 main 在 G4 前不调用。此路径属于 **代码审查通过、运行时未触发**。
* **经验总结**：就像电梯控制柜已经装好按钮解析模块，但楼层按钮线还没验收，不能因为软件能编译就宣布电梯可以载人。

## 2. 可迁移的系统级工程经验

* **避坑警示**：后续定义 RESULT_STATUS/OSD 时必须显式冻结字段宽度、时钟域、有效握手和未知值编码；禁止直接序列化 CPU enum/struct。
* **通用方法论**：把“业务语义正确”“wire ABI 正确”“CDC 正确”“板级画面正确”分成四道门。任意前门 PASS 都不能替代后门。

## 3. 推荐自行学习的相关知识

* **优先赛方资料**：
  * **推荐学习内容**：正式工程的 APB/OSD 接口文档、Efinity Interface Designer 与 CDC 报告。
  * **应用与意义**：为统一语义设计稳定寄存器映射，并验证 CPU→FPGA 的“隔洋通话”不会发生亚稳态或丢更新。

* **拓展基础知识**：
  * **推荐学习内容**：版本化寄存器 ABI、valid/ack 握手、双触发器同步与异步 FIFO。
  * **应用与意义**：避免软件枚举变化无声破坏硬件显示，确保一次逐轮结果只被 OSD 消费一次。
