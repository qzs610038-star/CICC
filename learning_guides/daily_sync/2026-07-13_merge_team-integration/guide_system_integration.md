## 1. 今日最核心的改动与经验

### 📌 核心点一：J4 静差与底座柔性是两类叠加风险
* **改动背景与问题**：多次 `HOME -> pick_hover` 中 J4 指令—读回末段静差约 `1.84°–2.20°`；正偏置能降低机械臂内部正运动学残差，却不能证明夹爪相对工作台稳定。
* **源码剖析**：[调试归档](file:///d:/第十届集创赛-雄芯院材料/mycobot_pc_tests/audit_logs/20260712_180deg_j4_mount_debug_record.md#L18-L46) 汇总角度与坐标证据；[底座连接分析](file:///d:/第十届集创赛-雄芯院材料/mycobot_pc_tests/audit_logs/20260712_180deg_j4_mount_debug_record.md#L48-L58) 说明 `get_coords()` 看不到机械臂底座相对工作台的倾斜。
* **经验总结**：这像把尺子固定在会晃的桌子上。尺子内部读数可以很准，但桌子一倾，尺端在房间里的真实位置仍会漂移。

### 📌 核心点二：真实动作必须经过 T0 与 D1—D5 分级门
* **改动背景与问题**：PC 脚本只用于健康检查和标定，不能替代板上 CPU 链路。
* **源码剖析**：[io_pin_map.md](file:///d:/第十届集创赛-雄芯院材料/final_project/integration/io_pin_map.md#L7-L27) 把 SoC/APB/UART2/PLIC/电平/急停/结构逐项登记为 FAIL；[板上调试方案](file:///d:/第十届集创赛-雄芯院材料/final_project/docs/technical_plans/mycobot_board_debug_execution_plan_20260712.md#L52-L105) 定义 T0、D1、D2、D3 与 D5；[当前放行结论](file:///d:/第十届集创赛-雄芯院材料/mycobot_pc_tests/audit_logs/20260712_180deg_j4_mount_debug_record.md#L66-L90) 保持真实动作 NO-GO。
* **经验总结**：这是大楼电磁锁：前一扇门没有明确 PASS，后一扇门没有钥匙。不能因为“通信看起来通了”就跳过结构固定和急停验收。

### 📌 核心点三：Git 合并也需要安全门
* **改动背景与问题**：当前工作区、FPGA 分支和 CPU 分支都包含复杂更新。直接 squash 或覆盖会让队友下次拉取时重新面对同一批差异。
* **源码剖析**：[CURRENT_STATE.md](file:///d:/第十届集创赛-雄芯院材料/CURRENT_STATE.md#L122-L129) 记录双层控制器的整合裁定；个人更新先以 `c835594` 推送备份，再用两个 `--no-ff` merge commit 保留队友 ancestry。
* **经验总结**：Git 历史像货物封条。保留 merge ancestry 等于保留“这箱货已经验收进仓”的凭证，队友之后更容易 fast-forward，而不是再拆箱对账。

## 2. 可迁移的系统级工程经验

* **避坑警示**：内部坐标、脚本返回 1、机械结构稳定、夹持稳定是四份不同证据；任何一份都不能替代另外三份。
* **通用方法论**：先备份再整合；先只读、回环、dry-run，再低速空载；失败时退回上一道门，不用不断加补丁掩盖同一根因。
