## 1. 今日最核心的改动与经验

### 📌 核心点一：快速推进不等于取消分层门禁

* **改动背景与问题**：本次目标是尽快把队友完整真源合入，不做过度审核。真正需要保留的不是繁琐流程，而是能阻止硬件事故的几道门。
* **源码剖析**：[CURRENT_STATE 的最新 Hard SoC 条目](file:///D:/第十届集创赛-雄芯院材料/CURRENT_STATE.md#L38)把旧“源码缺失/HOLD”删除，改为“离线构建已通过、板测仍未通过”；[AGENTS 的单摄安全门](file:///D:/第十届集创赛-雄芯院材料/AGENTS.md#L50)规定 USER2/片上 RAM Hello 前不得扩展到机械臂。
* **经验总结**：像医院急诊分诊：可以减少表格，但不能跳过血型核对和手术侧确认。项目里对应的是 bitstream 身份、USER TAP、内存区域和机械隔离。

### 📌 核心点二：把过时阻塞删掉，避免团队重复补交

* **改动背景与问题**：若 `CURRENT_STATE.md` 仍写着缺少 `settings.json`/BSP，下一位 Agent 会再次要求队友补文件，浪费时间甚至拼错副本。
* **源码剖析**：[Review Packet 的真源清单](file:///D:/第十届集创赛-雄芯院材料/competition_project_single_camera/docs/review_packets/m2_hard_soc_source_sync_review_20260716.md#L61)列出最小 BSP 与 IP 边界；[CLAUDE.md 候选工程入口](file:///D:/第十届集创赛-雄芯院材料/CLAUDE.md#L41)同步告诉执行 Agent 真实路径。
* **经验总结**：状态文档不是历史日记，而是交通信号灯。已解决的红灯必须及时熄灭；历史细节留在 Work Log/Review Packet。

### 📌 核心点三：合并完成后仍要把“可回退点”留清楚

* **改动背景与问题**：生成 IP 文件很多，人工逐行理解成本高。可靠回退依赖固定 SHA、明确文件边界和独立集成分支。
* **源码剖析**：本次锁定 `2d4b3b...` 与 `0604d33...`，生成源保持队友提交原样；管理性修订只落在状态、约束、技能、Review Packet 和本学习指南中。
* **经验总结**：Git 合并像把新车厢接到列车上：车厢可先接入，但在联挂、制动和信号测试完成前，不让它载客运行。这里“载客”就是新 bitstream 上板与机械臂联动。

## 2. 可迁移的系统级工程经验

* **避坑警示**：不要按文件夹修改时间从多个 workspace 拼工程；只能选一个可同时匹配工程文件、工具版本、哈希和板测证据的完整来源。
* **通用方法论**：维护两张清单：已关闭项（真源、离线编译、时序、CDC）与未关闭项（新 bitstream 板测、USER2、UART0）。推进决策只看未关闭项，不反复审查已关闭项。
