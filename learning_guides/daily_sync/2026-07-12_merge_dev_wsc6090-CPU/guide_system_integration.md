## 1. 今日最核心的改动与经验

### 📌 核心点一: matcher 的 GRAB 只是授权票，不是动作命令
* **改动背景与问题**：CPU 已能给出 GRAB/SKIP，但 `main.c` 尚未接 `arm_controller`，UART2/电平/接线也没有板级证据。
* **源码剖析**：[CURRENT_STATE.md](file:///D:/第十届集创赛-雄芯院材料/CURRENT_STATE.md#L91-L109) 明确 Host 完成与板级未完成边界；[main.c](file:///D:/第十届集创赛-雄芯院材料/final_project/cpu/app/src/main.c#L333-L381) 仍只写回识别动作与占位 round 条件。
* **经验总结**：GRAB 像登机牌，只说明“允许登机”；舱门、滑行、起飞仍分别需要 UART、状态机和安全互锁。

### 📌 核心点二: 上板必须逐门升级，不能从绿测跳到抓放
* **改动背景与问题**：本次 258/258 只覆盖 Host 逻辑，不覆盖 APB、UART2 1 Mbps、机械臂只读回包、PLIC/Ring Buffer 或真实动作。
* **源码剖析**：[Review Packet](file:///D:/第十届集创赛-雄芯院材料/final_project/docs/review_packets/cpu_task_matcher_merge_review_20260712.md) 将 GO/NO-GO 和未验证项固定下来。
* **经验总结**：整条链路像七道气密舱门：前一扇没有关严，后一扇就不能开。这样即使某层接线或中断有错，也不会直接变成机械臂运动。

## 2. 可迁移的系统级工程经验

* **避坑警示**：GET_ANGLES 是只读命令，但接线错误、电平不明或误接其他 UART 仍可能危险；低速空载单段前必须确认固定、姿态、急停/断电和速度限制。
* **通用方法论**：采用“无臂回环→真臂只读→中断 dry-run→低速单段→抓放”的逐级证据链。每级只新增一个变量，失败就回滚到上一门。
