## 1. 今日最核心的改动与经验

### 📌 核心点一：按低耦合顺序合并，冲突按语义解
* **改动背景与问题**：myCobot 与单摄分支代码路径基本不重叠，但都修改了 `CURRENT_STATE.md`。整文件选 ours/theirs 会丢掉另一条真实状态。
* **源码剖析**：[集成 Review Packet](file:///D:/第十届集创赛-雄芯院材料/final_project/docs/review_packets/main_merge_single_camera_mycobot_integration_20260714.md#L7-L27) 记录先合 myCobot、后合单摄以及人工冲突裁决；[根 README](file:///D:/第十届集创赛-雄芯院材料/README.md#L5-L9) 给队友一个不会误解的协作入口。
* **经验总结**：像合并两张透明地图，不能拿一张盖住另一张；要把道路都保留，再标清哪条是正式主路、哪条是试验岔路。

### 📌 核心点二：验证证据按层级上锁
* **改动背景与问题**：Host、QEMU、静态 XML 检查和历史板级画面来自不同层级，不能互相代替。
* **源码剖析**：[Review Packet 验证表](file:///D:/第十届集创赛-雄芯院材料/final_project/docs/review_packets/main_merge_single_camera_mycobot_integration_20260714.md#L37-L60) 分开记录软件 PASS、约束静态 PASS 与板级 NOT VERIFIED。
* **经验总结**：这是“机场分层安检”：证件检查、行李扫描、登机口核验都通过，才等于真正上机；少一层都不能借用上一层盖章。

## 2. 可迁移的系统级工程经验

* **避坑警示**：备份分支只保留，不参与合并；同步前先看 dirty 状态，禁止用 force push 或清理队友未提交内容。
* **通用方法论**：大合并采用隔离工作树、分支逐个 merge、每步独立验证、最终图谱重建。这样回滚点、责任边界和证据链都清楚。
