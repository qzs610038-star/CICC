## 1. 今日最核心的改动与经验

### 📌 核心点一：三路成果按职责合并，而不是按作者覆盖
* **改动背景与问题**：个人分支提供 UART2/J52 真源与安全门，Fable 分支提供 16 位事件契约，队友 CPU 分支提供 `arm_busy`、故障和超时补测。直接选一个分支会丢失另外两路证据。
* **证据剖析**：[合并适配说明](file:///D:/第十届集创赛-雄芯院材料/final_project/docs/review_packets/cpu_branch_merge_adaptation_20260714.md#L10-L69) 逐项登记保留、适配和理由；[CURRENT_STATE.md](file:///D:/第十届集创赛-雄芯院材料/CURRENT_STATE.md#L32-L40) 给出当前统一口径。
* **经验总结**：这像三个工种一起装安全门：电工负责传感器，锁匠负责门锁，验收员负责测试。合并不是决定“听谁的”，而是让三者在一张接口图上各守职责。

### 📌 核心点二：J52 真源冻结不等于可以接机械臂
* **改动背景与问题**：板端已确认 J52 Pin1 GND、Pin2 C14/RX、Pin3 F12/TX、Pin4 VCC 悬空；但机械臂端命名、电平和正式工程约束仍未通过。
* **证据剖析**：[UART2/J52 审查](file:///D:/第十届集创赛-雄芯院材料/final_project/docs/review_packets/mycobot_uart2_j52_wiring_review_20260713.md#L24-L60) 记录候选接法、VCC 禁止连接和 100/100 帧无臂验证顺序；[IO 门禁表](file:///D:/第十届集创赛-雄芯院材料/final_project/integration/io_pin_map.md#L14-L25) 仍将 UART、急停和机械结构登记为 FAIL。
* **经验总结**：知道门牌号只是找到房间，不能证明钥匙、电压和消防出口都合格。先断臂测波形，再做回环，最后才有资格申请真实臂只读。

### 📌 核心点三：软件安全测试与物理动作验收必须分层
* **改动背景与问题**：5758/5758 证明 Host 状态机在测试输入下行为一致，但不证明 UART、线序、夹持、180°旋转或最大臂展。
* **源码剖析**：[机械臂忙碌门](file:///D:/第十届集创赛-雄芯院材料/final_project/cpu/app/src/round_controller.c#L207-L222) 和[运动期锁定测试](file:///D:/第十届集创赛-雄芯院材料/final_project/cpu/tests/test_round_controller.c#L441-L520) 是软件层证据；真实硬件路径仍是 **代码审查通过、运行时未触发**。
* **经验总结**：消防演习通过，不代表真火现场已经发生过。演习证明流程值得继续，但不能拿它替代电气测量、急停和带载录像。

### 📌 核心点四：队友评价应围绕可撤销决策
* **操作建议**：队友拉取 `main` 后先读合并适配说明，重点评价 16 位 ABI、`arm_busy` 终态策略和理由码映射；若不认可，可在新的个人分支提出带测试的替代，不直接回滚整次合并。
* **经验总结**：把争议收敛成三道可单独更换的模块，比“整包接受或整包否定”更容易协作。

## 2. 可迁移的系统级工程经验

* **避坑警示**：提交到 `main` 的 Host 安全逻辑不会自动放宽 T0/D2 门禁；没有电平、共地、急停、线序和无臂回环证据时，真实机械臂动作仍是 NO-GO。
* **通用方法论**：跨团队合并要同时保存来源提交、冲突决策、验证命令、未验证边界和待评价问题，避免第二天只剩一段无法追责的聊天摘要。
