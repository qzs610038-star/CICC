## 1. 今日最核心的改动与经验

### 📌 核心点一：队友的安全增量保留，8 位序号升级到主线 16 位 ABI
* **改动背景与问题**：队友分支补了 `arm_busy` 和故障场景，但仍使用较早的 8 位序号；主线另一层契约已经是 16 位。两层位宽不同会在回绕时对同一事件给出不同判断。
* **源码剖析**：[round_controller.h](file:///D:/第十届集创赛-雄芯院材料/final_project/cpu/app/include/round_controller.h#L35-L76) 定义 16 位输入、ACK 和已消费序号；[round_controller.c](file:///D:/第十届集创赛-雄芯院材料/final_project/cpu/app/src/round_controller.c#L51-L78) 用半范围规则判断新旧事件。
* **经验总结**：事件序号像快递取件号。两个柜台若一个看两位、一个看四位，同一张票在 99/100 附近就会吵架；统一成 16 位并约定“前半圈才算更新”，才能安全处理号码回绕。

### 📌 核心点二：看到事件与接受事件是两件事
* **改动背景与问题**：上游必须知道 CPU 是没看到新事件，还是看到后因当前状态拒绝；否则可能盲目重发。
* **源码剖析**：[round_controller.c](file:///D:/第十届集创赛-雄芯院材料/final_project/cpu/app/src/round_controller.c#L134-L182) 对新事件显式返回 `ACCEPTED` 或 `REJECTED`，重复/过期事件不再次消费。[随机与边界测试](file:///D:/第十届集创赛-雄芯院材料/final_project/cpu/tests/test_round_controller.c#L334-L405) 覆盖 1000 事件流，[回绕测试](file:///D:/第十届集创赛-雄芯院材料/final_project/cpu/tests/test_round_controller.c#L617-L680) 覆盖 `65535 -> 0`、倒退和半圈歧义。
* **经验总结**：门卫说“证件看到了，但今天不能进”与“门卫没回应”不是同一状态。显式 ACK 能让上游正确停止重发，同时维持动作幂等。

### 📌 核心点三：机械臂忙时，软件不能再塞第二张动作单
* **改动背景与问题**：只有 `arm_enabled` 不足以证明机械臂可接新任务；机械臂可能仍在执行上一条动作。
* **源码剖析**：[arm_busy 门禁](file:///D:/第十届集创赛-雄芯院材料/final_project/cpu/app/src/round_controller.c#L207-L222) 在忙碌或未使能时保持零抓取请求并给出 `ARM_NOT_READY`。[对应测试](file:///D:/第十届集创赛-雄芯院材料/final_project/cpu/tests/test_round_controller.c#L551-L590) 验证该路径。
* **经验总结**：这像电梯门口的红灯。电梯已启用不代表当前可进货；只有“启用且不忙”才允许推入下一车货物。

### 📌 核心点四：当前通过的是 Host/Mock 与 compile-only
* **验证结果**：8 项 Host 回归合计 5758/5758，三个核心 C 文件通过 RISC-V GCC compile-only。
* **风险标注**：正式 `soc.h`、APB、CDC、OSD、UART2 和机械臂路径均为 **代码审查通过、运行时未触发**；本轮没有真实机械臂动作。

## 2. 可迁移的系统级工程经验

* **避坑警示**：不要为了保留队友代码而保留冲突 ABI，也不要为了统一 ABI 丢掉对方新增的安全场景。先提炼安全意图，再在唯一契约上重建测试。
* **通用方法论**：序号协议必须同时定义位宽、新旧关系、首次事件、回绕、歧义半圈、ACK 状态和重复消费规则；只写“序号递增”远远不够。
