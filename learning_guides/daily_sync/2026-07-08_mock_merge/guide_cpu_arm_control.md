## 1. 今日最核心的改动与经验

在 PC 调试脚本 v2.10~v2.12 的迭代中，通过解决**“机械臂到位判定提前/假到位”**以及**“固件 sync 死区导致异常熔断”**两大核心 Bug，沉淀出了未来板上 CPU 控制迁移的黄金规范。

### 📌 核心点一: 滤波二次确认机制（解决到位晃动假判定）
* **改动背景与问题**：
  机械臂在高速运动到目标点（如 `pick_hover`）时，由于惯性存在减速振荡（重力晃动）。如果只在轮询中读取一次关节角并与目标点对比，很可能会在某一个瞬态下探时误判定为“已收敛/已到位”，导致夹爪提前闭合下探，造成空抓或抓偏。
* **源码剖析**：
  在 [teach_replay_pick_return_ready.py:L973-L1025](file:///d:/第十届集创赛-雄芯院材料/mycobot_pc_tests/teach_replay_pick_return_ready.py#L973-L1025) 中，引进了 `confirm_count` 二次确认逻辑（`ASYNC_SHORT_CONFIRM_COUNT = 2`）：
  - 只有**连续 2 次**读取到的关节角度差值都在容差范围（`ANG_STABLE_TOL = 3.0°`）内，才被确认为真实收敛。
  - 中间偶发一帧读数失败（返回 `None`）不重置计数，但如果超出容差，计数清零，重新开始判定。
* **经验总结**：
  拒绝“单帧判定”，引入“时序连续性校验”，在控制系统中过滤振荡干扰。

### 📌 核心点二: 软超时后的 sync 兜底三段式判定（解决假熔断）
* **改动背景与问题**：
  在 `run-23` 测试中，系统在 Step 9 执行 `sync_send_angles` 时由于固件判定死区（在残差 $\sim 2^\circ$ 时可能返回 0），系统直接引发全局强熔断进程终止。
* **源码剖析**：
  在 [teach_replay_pick_return_ready.py:L1031-L1091](file:///d:/第十届集创赛-雄芯院材料/mycobot_pc_tests/teach_replay_pick_return_ready.py#L1031-L1091) 中重构为三段式判定：
  1. **第一段**：`res == 1` 代表到位，正常放行。
  2. **第二段**：若 `res != 1`，立即启动 **post-failure 复读**。如果读数在软容差内（角度差 $\le 3.0^\circ$ 或笛卡尔距离 $\le 25\text{ mm}$），说明已经基本到位，仅因固件假失败返回 0。此时允许**软通过**并触发强警告，不熔断。
  3. **第三段**：若复读超限，重发一次低速关节指令（`speed=8`），再复读，若仍超限，才触发安全熔断，释放舵机。
* **经验总结**：
  将“粗暴的一刀切熔断”优化为“有界确认重试 -> 分级降级 -> 最终熔断”，大幅提升系统的连续工作能力。

## 2. 可迁移的系统级工程经验

* **避坑警示**：
  在将该算法向板上 RISC-V CPU 移植时，由于裸机 C 语言没有 `try-except` 异常捕获机制，**必须对 UART 通信接口编写严格的数据帧校验（CRC）**。对于偶发的读数超时或校验失败，C 语言状态机内应做非阻塞式自动重试，严禁出现死循环挤爆 AXI 总线的情况。
* **通用方法论**：
  **有界与非阻塞控制**。在任何硬件控制状态机设计中，所有等待循环（如等待串口响应、等待电机到位）都必须加有界计数器/定时器超时。永远不要写类似 `while(uart_rx_not_ready);` 的无条件死循环。

## 3. 推荐自行学习的相关知识

* **推荐自学点 1**：**环形缓冲区（Ring Buffer）与非阻塞串口接收**
  * **为什么学**：板上 CPU 轮询节拍固定在 $50\text{ ms} \sim 100\text{ ms}$，若使用阻塞式串口读写，会严重拖慢主控制循环的时效性。
  * **学习切入点建议**：阅读嵌入式 C 语言中环形队列在 UART 驱动中的实现，学习如何通过中断接收数据、主循环非阻塞读取数据。
