## 1. 今日最核心的改动与经验

今日合并的 FPGA 侧核心改动（来自提交 [c652c68](file:///d:/第十届集创赛-雄芯院材料/tmp_fpga_diff.txt#L1)）重点攻克了摄像头初始化阶段 I2C 配置链路的“黑盒”诊断难题，并对跨时钟域（CDC）状态同步进行了加固。

### 📌 核心点一: I2C 启动诊断拆分与里程碑锁存
* **改动背景与问题**：
  在之前的版本中，如果摄像头未成功点亮（黑屏或显示 Fallback 静态彩条），顶层 LED 仅能显示非常粗糙的聚合状态，无法判断 I2C 通信是卡在低级初始化、还是配置寄存器表中途，亦或是最后的摄像头物理流启动（`0x0100 = 0x01`）被传感器拒绝。
* **源码剖析**：
  - 在 [i2c_master_reg_set.v](file:///d:/第十届集创赛-雄芯院材料/final_project/fpga/rtl/mipi_csi/cam_i2c_ctrl/i2c/i2c_master_reg_set.v#L32) 中引入了 `stream_on_done` (启动结束)、`stream_on_clean` (无错误启动) 和 `stream_on_error` (有 ACK 错误启动) 三个关键指示信号。
  - 在 [top.v](file:///d:/第十届集创赛-雄芯院材料/final_project/fpga/rtl/top/top.v#L178) 中重新设计了板载 LED18-33 的映射：
    - **LED22-29** 步进式显示 I2C 流程：`i2c_rst_n` -> `init_done` -> `wr_en` -> `wr_done` -> `cfg_done` -> `stream_on_index` -> `stream_on_seen` -> `stream_on_done`。
    - **LED30-31** 分离指示 `stream_on` 是以 `clean` (无报错) 还是 `error` (有 ACK 错误) 状态结束。
  - 为防止一瞬间发生的总线状态在 LED 上转瞬即逝，将上述 I2C 状态在 `mipi_clk` 时钟域做粘性锁存（sticky latch）。
* **经验总结**：
  在高速通信或复杂的硬件总线配置中，将“大结果”拆分为“步进式里程碑”，并配合锁存机制引出到 LED 或调试寄存器，是极其高效的可观测性设计。
  > **场景比喻（高速安检的步进指示器）**：就像火车站安检，如果通道口只有一个“进站成功/不成功”的大灯，一旦排队卡住，你根本无法判定到底是身份证没磁性、包里带了禁限物品，还是闸机硬件死机。新设计如同给安检通道装上了多个步进指示灯（读取身份证、行李X光、金属探测、最终开闸），哪个灯不亮，就能秒级定位问题所在。

### 📌 核心点二: 跨时钟域 (CDC) 同步与稳定性门控恢复
* **改动背景与问题**：
  I2C configuration 的 milestone 状态是在 `mipi_clk` (摄像头像素时钟域) 下锁存的，而顶层 LED 状态或主控制系统使用的是系统时钟 `i_sysclk_div2`。不经同步直接读取会导致采样时序冲突，进而引发亚稳态。另外，此前为了硬件诊断临时设为 `1'b0` 绕过的输入视频稳定性门控 `USE_INPUT_STABLE_GATE` 必须安全复位。
* **源码剖析**：
  - 在 [top.v](file:///d:/第十届集创赛-雄芯院材料/final_project/fpga/rtl/top/top.v#L22) 中，将 I2C stream-on 状态信号通过双锁存器打两拍同步到 `i_sysclk_div2` 时钟域。
  - 在 [video_2pix_to_1pix_cdc.v](file:///d:/第十届集创赛-雄芯院材料/final_project/fpga/rtl/dvi_tx/video_2pix_to_1pix_cdc.v#L14) 中对 CDC 像素格式转换桥的使能逻辑进行了加固。
  - 恢复 `USE_INPUT_STABLE_GATE` 参数为 `1'b1`，重新使能稳定性判定。
* **经验总结**：
  异步时钟域的单 bit 信号交互必须进行打两拍同步（CDC），多比特信号必须采用 FIFO 或握手；在硬件调试绕过安全门控后，务必在集成版中将安全门控恢复。
  > **场景比喻（“隔洋通话”双重核验）**：主时钟域和采集时钟域就像是两个有着不同时差的洲。如果一个人说话极快，另一个人直接接听很容易产生漏听或听错字（亚稳态）。“打两拍”（双寄存器同步）就像是要求说话人每个词都重复两遍，并且接听人在第二遍确定和第一遍听到的一致后才落笔记录，以此确保隔洋状态同步的绝对准确。

## 2. 可迁移的系统级工程经验

* **避坑警示**：
  调试阶段（如 HDMI Stripe 诊断中）修改 `USE_INPUT_STABLE_GATE` 参数虽然可以直观看到无对齐图像，但必须意识到这会引入瞬态时序不稳定。在正式集成并点亮双摄时，若不恢复为 `1'b1`，偶然的断流会污染下级 Framebuffer 写入，造成画面撕裂和大面积黑块闪烁。
* **通用方法论**：
  **可观测性设计（Design for Observability）**。编写 RTL 时不仅要实现 Happy Path 逻辑，还要在状态机的分支、跳变点等节点有意识地锁存状态，并将错误标志（如 `ACK_ERROR`）引出。在硬件调试手段有限的开发板现场，可观测性决定了排障时间是 5 分钟还是 5 天。
