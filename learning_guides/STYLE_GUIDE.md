# 学习指南风格与写作约束 (STYLE_GUIDE)

本文件是团队合并讲解指南（三轨学习系统）的风格与写作约束规范，后续凡是由 Agent 自动/交互生成的学习指南，必须无条件遵循本指南中的风格、术语要求及结构定义。

---

## 1. 核心语气风格：生动讲解与严谨分析并存

学习指南的设计初衷是辅助团队成员在 15 分钟内快速消化新合并的改动。因此，行文风格必须兼顾**“生动的工程直觉”**与**“严密的学术严谨度”**。

* **生动讲解（直观化、场景化）**：
  - 拒绝通篇枯燥的代码罗列和干瘪的修改描述。
  - 对于复杂的系统级行为、Bug 现象或控制逻辑，必须引入**直观的比喻模型**（如地铁安检、刹车振荡、大楼电磁锁等），降低非主责人员的认知负荷。
  - 阐述“为什么这样改”，从物理实体和控制系统的第一性原理出发进行生动阐述。
* **严谨分析（学术与工程规范）**：
  - 涉及的修改位置必须附带精确到文件的行号跳转链接（`file:///` 协议）。
  - 根因分析必须忠实于事实，以 Codex 评审裁定为唯一事实标准，不猜测，不修饰。
  - 对于未被实测充分覆盖的路径，必须严格如实标注 **“代码审查通过、运行时未触发”** 的客观风险，严防口头承诺。

## 2. 关键专业术语生动讲解库

指南中涉及以下核心术语时，应统一采用如下的生动比喻与严密工程解释组合：

| 专业术语 | 严密工程定义 | 生动比喻解释 |
|:---|:---|:---|
| **CDC (跨时钟域)** | 信号从一个异步时钟域传输到另一个时钟域，可能引发亚稳态。 | **“隔洋通话”**：两人时差不同，一个人说话太快，另一个人容易漏听，需要“打两拍”（双锁存器）或握手来确保对齐。 |
| **到位振荡 (Oscillation)** | 控制实体（机械臂等）高速运动到目标点时，由于惯性而在终点附近产生来回阻尼摆动的物理现象。 | **“坐车刹车”**：司机猛踩刹车时，车身会前后剧烈晃动，必须等晃动静止（连续 confirm）才算停稳。 |
| **有界三段式重试** | 针对偶尔读数异常或固件死区设计的分级兜底机制，包含主路放行、复读警告和限次重试。 | **“保险丝复位”**：停电了不直接拉全楼闸门，先复查，再合闸重试 1 次，最后实在不行再彻底熔断断电。 |
| **非阻塞轮询 (Non-blocking)** | 状态机等待硬件信号时，加入超时限制并允许执行其他事务，避免死循环阻塞。 | **“留号排队”**：不用在柜台前死等，留下电话（设置定时器/超时计数器），柜台好了打给你，在此期间可以干别的。 |
| **软到位 (Soft Success)** | 在物理残差或读数误差在允许的软容差（如 $\le 3^\circ$ / $25\text{ mm}$）内时，为了流程连贯判定为到位。 | **“差之毫厘，殊途同归”**：投篮虽然没有砸中篮筐正中心，但球进了（在容差内），就应该判定得分通过。 |
| **故障注入 (Fault Injection)** | 在测试中故意人为制造异常输入或时序错误，以检验系统的鲁棒性和兜底机制。 | **“消防演习”**：在晴天故意拉响警报（注入 mock 假数据或模拟丢包），测试大楼的应急通道是否畅通。 |

## 3. 三轨职责划分与目录规范

* **A (FPGA与视频前端)**：聚焦摄像头接入、ROI、视频统计特征与 OSD 叠加。
* **B (嵌入式CPU与通信控制)**：聚焦板上 C 语言逻辑、UART 协议封包与数据交换。
* **C (机械臂控制调试与项目系统维护更新)**：聚焦机械臂姿态调试、点位标定、故障应急策略与系统级版本归档/交接。
