## 2. 系统设计缺陷与 Gemini 审阅改进建议

为了确保系统稳定可靠、现场光照适应性强并避免关键硬件瓶颈，Gemini 提出以下五点系统级改进建议：

### 建议 1：设计硬件特征提取模块 (Feature Extract RTL) 规避 DDR 带宽抢占与 Cache 一致性刷新

*   **痛点**：初赛 Demo 采用 CPU 逐个像素读取 DDR 中 `240 x 135` 降采样图像的方案（每帧 129 KB 数据），在 100MHz 的 RISC-V 软核上计算开销大，且与 HDMI 读 DDR 抢占 AXI 总线带宽，导致系统变慢，同时还需频繁调用 `dCacheInvalidate` 进行数据同步。
*   **改进方案**：
    -   在 FPGA 侧的 `roi_crop` 流式数据路径上，直接设计硬件累加器和边界比较器，提取 ROI 内各颜色通道的累加均值、背景像素占比，以及目标物体的 Bounding Box (`min_x`, `max_x`, `min_y`, `max_y`)。
    -   将这些小体积特征（约 16-32 字节）通过 APB 或 AXI-Lite 挂在 CPU 的寄存器窗口。
    -   如需细化轮廓，可在 FPGA 侧将二值化后的超轻量位图（如 `60 x 30` 像素）写入片上 BRAM（双口 RAM），由 APB 暴露给 CPU。
*   **收益**：CPU 读特征缩短至微秒级，完全避免了 DDR 总线冲突和 Cache 刷新风险。

### 建议 2：实现 CPU 动态自适应颜色阈值与背景抑制（增强现场光照抗干扰能力）

*   **痛点**：初赛在 FPGA RTL 级使用固定阈值对每个像素进行 `color_id` 分割。决赛现场无额外打光，自动白平衡（AWB）和曝光波动极易导致 RGB/HSV 阈值失效（例如红色变粉、蓝色变灰），直接影响后续计数和几何形状判定。
*   **改进方案**：
    -   颜色分割阈值寄存器必须通过 APB 接口暴露，允许 CPU 实时写入修改。
    -   CPU 侧引入相对通道比值（如 $R/G$、$B/G$）和亮度归一化处理，减弱绝对照度波动影响。
    -   软件在无物块状态下自动读取背景 ROI 特征作为基准值，实现背景差分，剔除背景噪点。比赛现场可以通过串口命令行快速调节分类阈值表 (`param_table.c`)，免去重新编译 FPGA 的过程。

### 建议 3：引入多帧时序平滑与迟滞比较（确保 0.5 cm 级高精度尺寸估计）

*   **痛点**：决赛需精准区分 2.0 cm、2.5 cm、3.0 cm 正方体，0.5 cm 差值在 30cm 高空俯拍下仅对应几个像素宽度，单帧噪声极易导致测量输出在临界尺寸来回跳变。
*   **改进方案**：
    -   **时序滤波**：在 CPU `vision_classifier.c` 中建立滑动窗口，对连续 10 帧以上的 Bounding Box 宽高取**中值或均值**，消除像素抖动。
    -   **迟滞区间（Hysteresis）**：在尺寸分割点（如 2.25 cm 和 2.75 cm）设置一定的防抖迟滞带，避免输出频繁跳变。
    -   **标定机制**：在 `pc_tools` 中编写自动标定脚本，开机时使用 3.0 cm 标准块自动标定像素-物理距离比例尺 $K_{calib}$。

### 建议 4：双独立 UART 外设隔离设计（隔离 1M 波特率机械臂串口与调试日志）

*   **痛点**：Sapphire SoC 的默认调试终端串口为 115200 波特率。而大象机械臂 myCobot 280 的控制串口波特率必须是 1000000（1M）。若强行混用，会导致指令和调试日志包混叠，1M 串口的高频字节中断还会导致 CPU 丢包或死机。
*   **改进方案**：
    -   在 FPGA 核心 IP 实例化中，**配置两路独立的 APB UART**。
    -   `UART0`（115200 波特率，接开发板 Type-C）专用于输出调试串口日志。
    -   `UART1`（1M 波特率，连接外部 GPIO 物理引脚）专用于收发 myCobot 协议控制帧，且**必须为 UART1 硬件配置至少 16 字节的接收 FIFO 缓冲区**。

### 建议 5：打通 CPU 心跳与诊断信息到 HDMI OSD 叠加链路

*   **痛点**：调试和现场比赛时，HDMI 显示器是唯一可以直接进行诊断的通道。如果 CPU 内部状态不可见，极难排查程序跑飞、死机或阈值判决错误。
*   **改进方案**：
    -   **CPU 心跳指示**：CPU 定期向 FPGA `CPU_HEARTBEAT` 寄存器累加计数，FPGA 侧的 `osd_overlay` 模块据此在画面角落闪烁显示“CPU OK”状态色块。
    -   **动态边框与数据叠加**：在 HDMI OSD 画面上实时绘制出绿色 ROI 框线与黄色目标 Bounding Box，并直接渲染显示当前的 `COLOR`、`SHAPE`、`SIZE` 识别结果与机械臂动作状态码（如 Wait/Grab/Return）。
