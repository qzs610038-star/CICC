# 视觉模块决策过程记录 2026-07-02

本文记录视觉模块推进过程中已经确认的约束、方案判断、当前决策和后续待决问题，供队友同步和后续继续决策使用。

## 1. 项目内已确认硬件与视频链路

### 1.1 摄像头与视频链路

参考工程：`TJ375N529_SC431HAI2LCD_Demo_V3`

已从项目内代码确认：

- 摄像头型号线索来自 Demo 名称：`SC431HAI`
- 当前 Demo 已接入两路同参数 MIPI 摄像头
- 每路摄像头为 4-lane MIPI CSI
- 现有顶层参数按 `1920 x 1080` 配置
- RAW10 输入，`PACK_BIT = 40`
- 现有链路为：

```text
MIPI CSI
 -> soft_mipi_rx_top
 -> frame_buffer
 -> debayer_top_2to1
 -> white_balance
 -> LCD/HDMI 显示
```

白平衡后可作为视觉识别旁路输入：

```text
wb0_vs_out / wb0_hs_out / wb0_de_out / wb0_data_out[47:0]
wb1_vs_out / wb1_hs_out / wb1_de_out / wb1_data_out[47:0]
```

双像素 RGB888 格式：

```text
[47:40] odd_r
[39:32] odd_g
[31:24] odd_b
[23:16] even_r
[15:8]  even_g
[7:0]   even_b
```

### 1.2 机械臂与夹爪参数

机械臂资料已归档：

- `final_project/docs/source_materials_digest/mycobot_280_for_arduino_specs_source.txt`

关键参数：

- 机械臂：myCobot 280 for Arduino
- 自由度：6 DOF
- 赛方限制：至多使用 5 个自由度
- 队内计划：冻结 1-2 个次要自由度，机械臂控制细节由机械臂同学负责
- 最大工作半径：`280mm`
- 最大负载：`250g`
- 机械臂重复定位精度：`±0.5mm`
- 夹爪夹持范围：`20-45mm`
- 夹爪重复精度：`1mm`
- 夹爪重量：约 `100g`

- 控制接口：串口控制

- 物体竖直放置，正方体采用固定姿态抓取。
- 冻结自由度后不应依赖视觉给出姿态角补偿。

## 2. 赛题与场地约束

### 2.1 物体约束

已确认：

- 物体静止摆放，等待识别。
- 当前赛段：单次只出现一个物体。
- 后续决赛：可能多个物体同时出现。
- 物体形状包含：
  - 正方体
  - 圆柱
  - 圆锥
- 三类形状均有三档尺寸：
  - `2.0cm`
  - `2.5cm`
  - `3.0cm`
- 物体竖直放置。
- 颜色与形状会组合出现，例如红色圆锥、蓝色圆柱、黄色正方体等。
- 机械臂只抓取正方体，其他物体只做颜色和形状识别。

### 2.2 场地与光照约束

已确认：

- 识别位置由队内自行决定。
- 分拣位置不确定由赛方提供还是队内自行决定。
- 抓取物体后需要横向移动大于 `10cm`，到分拣位置后放下。
- 不能放置自定义背景板。
- 背景色和光照条件比赛当天才能获取。
- 可以确保机械臂底座、识别点、摄像头相对位置在正式运行时固定。
- 前期调试由于支架缺失，摄像头位置可能有约 `±1cm` 小范围误差。

对视觉算法的影响：

- 不应依赖固定 RGB 绝对阈值直接比赛。
- 需要比赛当天快速标定颜色阈值、尺寸阈值和 ROI。
- 阈值建议使用通道差值、归一化颜色比例和多帧稳定判断。
- 每次摄像头位置移动后都应重新做像素标定。

## 3. 摄像头使用策略决策

### 3.1 当前阶段策略

当前阶段选择：

```text
第一阶段只使用一路摄像头作为主识别相机。
第二路摄像头先预留，后续用于圆柱/圆锥区分和决赛多物体增强。
```

判断理由：

- 当前赛段单物体，先跑通单路识别和固定点抓取收益最高。
- FPGA/CPU 视觉链路还需要先验证，过早双摄会增加调试复杂度。
- 机械臂先使用固定点抓取，视觉中心点先用于校验和日志，不立即闭环控制。

### 3.2 第二路摄像头定位

最终需要区分圆柱和圆锥，因此第二路摄像头仍然有必要。

推荐定位：

```text
相机 2：侧视或轻微俯视侧视
高度：接近物体中上部，约 3-10cm，可根据支架和视野调整
角度：基本水平，略向下 5-15 度
作用：区分圆柱 / 圆锥
```

判断理由：

- 俯视下圆柱和圆锥都可能近似圆形，区分不稳定。
- 正面侧视下圆锥近似三角形，圆柱近似矩形，判别更直接。
- 已有一路主相机负责顶面形状，因此第二路不必强求 45 度斜俯拍。

## 4. 推荐机械与视觉布局

### 4.1 全局坐标系

建议统一使用机械臂底座中心作为全局坐标原点：

```text
O = 机械臂底座中心
X = 机械臂正前方
Y = 机械臂右侧
Z = 竖直向上
单位 = mm
```

### 4.2 初始点位建议

已确认：

- 识别点位于机械臂左前方。
- 识别点到机械臂底座中心距离可按 `160mm` 布置。
- 分拣点在识别点右侧，距离 `120-160mm`，必要时可以更大。
- 夹爪从上往下抓取。

初始推荐点位：

```text
识别点 P_pick:
  X = 150
  Y = -55
  Z = 0

分拣点 P_bin:
  X = 150
  Y = +85 到 +125
  Z = 0
```

该布局满足：

- 底座到识别点距离约 `160mm`
- 识别点到分拣点横向距离约 `140-180mm`
- 满足横向移动大于 `100mm` 的比赛要求
- 识别点和分拣点均位于 `280mm` 工作半径内较舒适区域

后续若赛方指定分拣位置，需要保留点位表重配置能力。

### 4.3 主相机安装建议

由于已购买 `50cm` 摄像头线，摄像头可以实现离地 `30cm` 以上，因此主相机重新优先推荐高位俯视。

推荐：

```text
相机 1：高位俯视 / 轻微偏置俯视
目标点：P_pick
高度：300-400mm
水平偏置：30-60mm 可接受
角度：尽量接近垂直向下
作用：颜色、尺寸、顶面形状、目标中心、抓取允许判断
```

注意：

- 支架和排线不要占据夹爪从上往下抓取的竖直通道。
- 若相机相对识别点偏置，需要通过标定修正透视和像素尺寸阈值。
- 前期支架误差 `±1cm` 可接受，但每次位置变动后需要重新标定。

## 5. 当前视觉识别目标

第一版目标：

```text
识别指定颜色 + 指定尺寸 + 正方体。
仅当三者同时满足时，允许机械臂抓取。
```

识别分类建议：

```text
颜色：
  red / blue / yellow / white / black / unknown

尺寸：
  unknown / 2.0cm / 2.5cm / 3.0cm

形状：
  unknown / cube / cylinder / cone
```

当前赛段抓取条件：

```text
object_valid
&& color == target_color
&& size == target_size
&& shape == cube
```

## 6. FPGA/CPU 分工决策

当前选择：

```text
FPGA 做像素级实时特征提取。
RISC-V CPU 做颜色/尺寸/形状最终分类、任务判断和机械臂控制。
```

FPGA 第一版职责：

- 接收白平衡后的 RGB 双像素流。
- ROI 裁剪。
- 颜色 mask。
- area 统计。
- bbox 统计。
- center 计算或输出 bbox 后由 CPU 计算。
- 输出每帧稳定特征。

CPU 第一版职责：

- 写入 ROI、颜色阈值、面积阈值、尺寸阈值等配置。
- 读取 FPGA 特征寄存器。
- 多帧投票稳定颜色和形状判断。
- 根据尺寸阈值查表分类。
- 判断是否允许抓取。
- 调用机械臂固定点抓取与分拣点放置动作。

判断理由：

- FPGA 适合做逐像素实时统计。
- CPU 更适合处理阈值调试、规则切换、异常恢复和机械臂串口协议。
- 比赛当天光照不确定，阈值需要可写、可调、可记录。

## 7. 抓取精度目标

建议调试目标：

```text
最低可用：物体中心摆放误差 <= ±8mm
推荐目标：物体中心摆放误差 <= ±5mm
稳定目标：物体中心摆放误差 <= ±3mm
```

判断理由：

- 最小物体尺寸为 `20mm`。
- 夹爪范围为 `20-45mm`，可覆盖三档物体。
- 机械臂本体重复定位精度较好，主要误差来自物体摆放、夹爪安装偏心、抓取姿态、视觉标定和物体被碰动。

## 8. 建议推进顺序

### 阶段 1：单路相机识别闭环

- 固定识别点和相机 1。
- FPGA 输出颜色 mask、area、bbox、center。
- CPU 打印每帧特征。
- 验收：
  - 单物体放入 ROI 后 bbox 合理。
  - 换不同颜色物体时 dominant color 正确变化。
  - 三档尺寸可通过阈值区分。

### 阶段 2：固定点抓取

- CPU 根据视觉识别结果判断是否允许抓取。
- 机械臂执行固定 P_pick 抓取。
- 横向移动大于 `10cm` 到 P_bin 放置。
- 视觉中心点只做日志和偏差检查。

### 阶段 3：第二路相机形状增强

- 相机 2 侧视接入。
- 增加圆柱/圆锥侧视特征。
- CPU 融合相机 1 顶面形状和相机 2 侧面轮廓。

### 阶段 4：决赛多物体扩展

- 主相机在俯视画面中分割多个候选目标。
- CPU 逐个候选输出颜色、形状、尺寸和优先级。
- 机械臂只抓满足任务条件的正方体。

## 9. 下一步待决问题

需要继续确认 FPGA 到 CPU 的第一版寄存器接口：

1. 第一版是否只处理相机 1，第二路相机先预留接口但不接入判断。
2. CPU 读取视觉结果采用轮询 `frame_done`，还是后续加中断。
3. 目标颜色和目标尺寸是赛前固定，还是每轮动态输入。
4. FPGA 是否直接输出 `dominant_color`，还是只输出每种颜色 mask 面积，由 CPU 判断。
5. FPGA 是否输出 `shape_class`，还是输出原始 bbox/area/分段宽度后由 CPU 判断。
6. 是否需要调试叠加显示：
   - bbox 框
   - 中心点十字
   - 颜色 mask overlay
7. CPU 需要动态写入哪些参数：
   - ROI 范围
   - 颜色阈值
   - 面积阈值
   - 尺寸分类阈值
   - 形状分类阈值

建议优先决策：第一版使用轮询寄存器，不做中断；FPGA 输出原始特征，CPU 做最终分类。
