## 1. 执行摘要

最大化得分不应理解为“先把机械臂做出来”，也不能理解为“Host 单测通过就有保底分”。现场得分必须同时具备：

```text
可烧录、可启动的板级系统
→ 稳定视频与真实特征
→ 正确识别
→ 正确目标判断
→ 清晰无歧义输出
→ 非目标明确不动作 / 目标唯一动作
→ 20 轮在 10 分钟内完成
```

推荐采用两条 P0 主线并行推进：

- **P0-A CPU 得分引擎**：四任务契约、目标输入、关系判定、逐轮事务、理由码和 mock 测试。
- **P0-B FPGA 生产构建**：正确诊断 PNR/Debugger/VDB/接口约束问题，获得可重复生成的生产 bitstream 和稳定视频入口。

两条主线汇合后，先形成“识别 + 判断 + OSD + 正确 SKIP”的无机械臂得分闭环，再接入一条固定正方体抓放路径，补齐目标轮执行分。

## 2. 计分模型与拿分策略

### 2.1 任务目标数量

根据官方物体集合：

| 任务 | 总轮数 | 目标轮 | 非目标轮 | 说明 |
|---|---:|---:|---:|---|
| 任务一：指定颜色正方体 | 5 | 1 | 4 | 五色正方体各 1 个，目标颜色 1 个 |
| 任务二：正方体 + 指定颜色 | 5 | 1 | 4 | 1 个指定颜色正方体为目标，其余为非目标 |
| 任务三：边长差 = 1cm | 5 | 2 | 3 | 参考 2cm 时两个 3cm 为目标；参考 3cm 时两个 2cm 为目标 |
| 任务四：边长差 ≤ 0.5cm | 5 | 3 | 2 | 参考 2cm 或 3cm 时，参考尺寸与 2.5cm 合计 3 个目标 |
| 合计 | 20 | 7 | 13 | 所有目标物均为正方体 |

### 2.2 评分表内部不一致

正文描述单轮为识别 25% + 判断 25% + 执行 50%，但摘录评分表中任务三每轮为识别 1 分 + 判断 1 分 + 分拣 1 分，即三项等分。

处理规则：

- 软件和现场输出必须覆盖三个环节，不依赖比例差异取巧。
- 计划估分以官方具体表格为主，同时把任务三比例列为赛前必须确认的问题。
- 未获得官方答复前，不对外承诺固定“70%保底”或“83%保底”。

### 2.3 无目标动作时的理论上限

假设所有 20 轮识别、判断均正确，13 个非目标轮都正确 SKIP 并输出理由，但 7 个目标轮完全不执行机械臂动作，按表理论得分为：

| 任务 | 理论得分 | 满分 |
|---|---:|---:|
| 任务一 | 9 | 10 |
| 任务二 | 18 | 20 |
| 任务三 | 13 | 15 |
| 任务四 | 14 | 20 |
| 合计 | 54 | 65 |

`54/65 = 83.1%` 只是理想数学上限，不是当前工程可保证成绩。真实得分还受摄像头、光照、特征、板级链路、输出是否被评委认可和时间限制影响。

### 2.4 得分恢复顺序

1. 先保证所有轮次有可解释识别与判断结果。
2. 保证 13 个非目标轮正确 SKIP，获取低风险执行分。
3. 所有目标物都是正方体，使用一条固定抓放路径覆盖 7 个目标轮，不做多套任务动作。
4. 最后优化动作速度、自动检测和界面美化。

## 4. 目标软件契约

### 4.1 目标配置

建议新增纯软件结构，先完成 Host/mock 契约，不预设 APB 地址：

```c
typedef enum {
    TASK_COLOR_CUBE = 0,
    TASK_SHAPE_COLOR_CUBE,
    TASK_SIZE_DELTA_EQ_10MM,
    TASK_SIZE_DELTA_LE_5MM
} task_mode_t;

typedef struct {
    task_mode_t mode;
    uint8_t target_color;
    uint8_t reference_size_mm;
    uint8_t valid;
    uint8_t apply;
} competition_target_t;
```

设计要求：

- 颜色至少 3 bit，能够表达任意、红、黄、蓝、黑、白和非法值。
- 任务模式至少 2 bit。
- 参考尺寸表达 20/25/30mm，但任务三/四只允许 20/30mm 作为评委参考输入。
- `apply` 必须形成锁存边沿；拨码或按键抖动不得在本轮中修改目标。
- `round_reset`、`abandon`、`place_confirm` 和 `remove_confirm` 属于操作事件，不得混入持久目标配置。
- 正式接口应在最终确认的 APB 数据宽度上定义一个或多个 32 位语义寄存器；当前 CPU 已按 32 位 MMIO 访问，扩展的是寄存器字段语义，不是把 APB 数据总线从 5 位扩成 32 位。
- 不为目标配置新增 16/32 根顶层物理引脚；板上少量按钮/拨码只产生菜单选择和已锁存事件。

### 4.2 任务判断

```text
任务一：shape == CUBE && color == target_color
任务二：shape == CUBE && color == target_color
任务三：shape == CUBE && abs(size_mm - reference_size_mm) == 10
任务四：shape == CUBE && abs(size_mm - reference_size_mm) <= 5
```

注意：任务一/二输入语义不同，但目标判断可以复用；识别输出仍必须显示实际颜色、形状和尺寸。

### 4.3 理由码

建议使用稳定枚举，不在状态机中拼临时字符串：

```text
REASON_TARGET_MATCH
REASON_COLOR_MISMATCH
REASON_SHAPE_MISMATCH
REASON_SIZE_NOT_EQ_10MM
REASON_SIZE_OUTSIDE_5MM
REASON_OBSERVATION_UNKNOWN
REASON_STABILITY_TIMEOUT
REASON_OPERATOR_ABANDON
REASON_ARM_NOT_READY
REASON_ARM_FAULT
```

CPU 回写枚举和实际数值；OSD 将枚举渲染为固定短文本，UART 输出完整说明。

## 5. 一轮一事务控制器

### 5.1 模块边界

新增：

```text
final_project/cpu/app/include/round_controller.h
final_project/cpu/app/src/round_controller.c
final_project/cpu/tests/test_round_controller.c
```

不要直接把完整状态机堆入 `main.c`。`main.c` 只负责：

- 采集和融合稳定观测；
- 读取已经锁存的目标配置；
- 调用 `round_controller_tick()`；
- 将 round result 回写给 OSD/UART；
- 将唯一动作请求交给 `arm_controller`。

### 5.2 推荐状态

```text
CONFIG
→ WAIT_PLACE_CONFIRM
→ ACQUIRE_STABLE
→ LATCH_RECOGNITION
→ LATCH_DECISION
→ EXECUTE_OR_SKIP
→ WAIT_ARM_DONE
→ ROUND_DONE
→ WAIT_REMOVE_CONFIRM
→ WAIT_PLACE_CONFIRM
```

### 5.3 核心不变量

- 同一物体最多锁存一次识别结果。
- 同一轮最多发出一次 `arm_controller_request_grab()`。
- 连续视频帧不得重复触发动作。
- 非目标物必须进入 `ROUND_DONE`，不能无限等待。
- UNKNOWN/不稳定必须有超时；允许操作员按细则放弃本轮并进入下一轮。
- 目标配置只有在 `CONFIG` 或新任务开始时才能更新。
- 机械臂忙或 fault 时禁止新动作，但仍应保留已锁存的识别和判断证据。

### 5.4 人工确认优先

第一版采用板上按钮/拨码形成“摆放完成”“物体已移除”“放弃本轮”事件。不要先依赖自动物体存在检测，因为过渡帧和手部遮挡会增加重复触发风险。

按钮不得作为 CPU 可能漏读的单周期脉冲。消抖后的事件必须在硬件或最靠近输入端的软件层锁存，并携带单调递增的 `event_seq`；CPU 处理后回写 ACK，收到 ACK 前事件保持有效。自动物体存在/移除检测只能作为加速路径，人工确认始终是保底出口。

### 5.5 恢复与活性契约

状态机的目标不是追求“完美自动”，而是保证现场异常后仍能继续完成剩余轮次。必须满足：

- 每个等待状态都有明确截止时间和允许的人工出口，不存在永久阻塞等待。
- `ACQUIRE_STABLE` 超时后锁存 `REASON_STABILITY_TIMEOUT`，显示 UNKNOWN，并允许 `ABANDON_ROUND`。
- `WAIT_REMOVE_CONFIRM` 始终接受人工 `REMOVE_CONFIRM`；自动空场判断失败不得阻塞下一轮。
- `WAIT_ARM_DONE` 超时不得直接清空轮次，而应发出取消/停机请求，转入 `ARM_FAULT` 或安全保持，再等待操作员确认。
- OSD 必须持续显示当前状态、状态停留时间、故障原因和当前可用的恢复操作，禁止静默等待。

恢复命令分级如下：

| 命令 | 允许条件 | 结果 |
|---|---|---|
| `ABANDON_ROUND` | 机械臂未运动，或已确认安全停止 | 保留本轮识别/判断/错误证据，标记放弃，进入结果保持或移除确认 |
| `SOFT_RESET_ROUND` | 机械臂 idle/safe | 清理本轮事务，保留任务配置、整场计时和历史日志，返回 `WAIT_PLACE_CONFIRM` |
| `SESSION_RESET` | 机械臂 idle/safe 且操作员二次确认 | 返回 `CONFIG`，不伪造已完成轮次 |
| `E_STOP` | 任意时刻 | 走独立机械安全通道；软件状态机只记录故障，不替代急停 |

机械臂运动中禁止把 round controller 盲目复位到等待新物体。安全恢复路径固定为：

```text
动作超时/人工中止
→ CANCEL_REQUEST
→ HOLD/SAFE_STOP 或 ARM_FAULT
→ 操作员确认机械臂安全
→ 允许放弃或软复位本轮
```

### 5.6 建议状态时限

具体数值须在实机计时后冻结，首版 Host/mock 默认值用于暴露死锁而非代替实测：

| 状态 | 首版默认预算 | 超时动作 |
|---|---:|---|
| `WAIT_PLACE_CONFIRM` | 不限，但显示整场剩余时间 | 允许跳过/结束任务 |
| `ACQUIRE_STABLE` | 3 s | UNKNOWN + 允许放弃或重采 |
| `WAIT_ARM_DONE` | 按动作表单独预算 | 取消/安全停机 + `ARM_FAULT` |
| `WAIT_REMOVE_CONFIRM` | 5 s 提示，非硬死等 | 人工确认、放弃或软复位 |

## 9. P1：SoC/APB 与目标输入

### 9.1 最小 APB 闭环顺序

```text
REG_MAGIC / heartbeat
→ CPU 读取目标配置
→ CPU 写固定测试结果
→ OSD 显示固定结果
→ FPGA 特征快照
→ CPU 分类结果回写
```

不要一开始同时接目标输入、双通道快照、OSD、机械臂和中断。

### 9.2 必需真源

- Efinity 生成的正式 `soc.h`。
- SoC/APB 实例和真实基址。
- APB 时钟、复位、地址宽度和 CDC 方案。
- 实际物理按钮/拨码资源；当前 `i_sw[0]`、`i_sw[1]` 已有用途，不能假设仍可自由占用。
- 目标配置的消抖和锁存方式。

### 9.3 推荐现场输入

优先使用板上按钮/拨码配合 OSD 菜单：

```text
MODE / NEXT / CONFIRM / ROUND_RESET
```

正式比赛不依赖 PC 串口输入目标。确认前显示预览，确认后锁存；当前任务完成前不得被抖动修改。

### 9.4 寄存器语义草案

以下只冻结语义，不冻结地址；真实基址、数据宽度和 strobe 行为必须以 Efinity 生成物和 `soc.h` 为准：

```text
TARGET_CFG_STATUS（FPGA/输入侧 → CPU）
[2:0]   target_color
[4:3]   task_mode
[6:5]   reference_size_code
[7]     config_valid
[15:8]  config_seq
[31:16] version / reserved

OPERATOR_EVENT（输入侧 → CPU，CPU ACK）
[3:0]   event_code
[15:8]  event_seq
[31:16] reserved

RESULT_STATUS（CPU → FPGA/OSD）
round_seq + recognition + decision + reason + action + arm_state
```

保留配置和操作事件的独立生命周期：配置只在 `CONFIG` 提交，事件按序号逐个消费，结果按 `round_seq` 整体锁存。若兼容旧软件有价值，可暂时保留旧低位字段别名，但不得把当前占位偏移当作硬件事实。

### 9.5 CDC 与增量集成门

- `TARGET_CFG_STATUS` 和 `OPERATOR_EVENT` 优先保持在 APB/CPU 时钟域；只把已经稳定、提交完成的快照送往需要显示的时钟域。
- CPU→OSD 多位结果采用 staging registers + commit toggle/sequence + active snapshot；禁止多位语义信号逐位裸跨 CDC。
- 不因寄存器字段扩展修改视频数据路径，不新增宽顶层物理端口。
- 集成按“基线生产 PNR/视频 → 配置寄存器 → 事件锁存/ACK → 固定结果回写 → OSD 快照 CDC”逐级推进；每一级比较资源、Setup/Hold slack、CDC warning、bitstream 可重复性和视频上板现象。
- 任一级出现 PNR、时序或黑屏回归，立即回退到上一可验证 checkpoint，禁止同时叠加下一层修改。

### 12.1 一条动作覆盖全部目标轮

### 12.4 放置策略

```text

→ 抬升并回安全位
```

### 20.1 黑白识别的特别约束

`vision_classifier.c` 在红/蓝/黄均不明显时，以填充率区分白/黑。当前 `board_io.h` 默认 `FG_AREA_AVAILABLE=0`，只能用颜色面积和近似前景面积降级：黑色可能勉强工作，白色容易与低饱和背景混淆。

因此 `LIVE_FG_AREA` 不是普通优化项，而是五色保底的P0接口字段：

- FPGA提供bbox内真实前景像素数，并和bbox/颜色计数属于同一帧快照。
- CPU只在`FG_AREA_AVAILABLE=1`且帧序号一致时启用正式白/黑判定。
- 在真实板级数据验证前，不得宣称白/黑稳定；若接口来不及，必须在OSD明确显示低置信度，而不是误抓。

## 21. 最低保底方案：F1真实识别/判断/SKIP闭环

### 21.1 保底定义

7月17日必须冻结的最低保底不是“彩条能显示”或“Host单测通过”，而是：

```text
至少一路真实摄像头稳定
→ FPGA输出ROI/同帧统计（含LIVE_FG_AREA）
→ 板上CPU读取真实快照
→ 拨码/按键锁存任务与目标
→ CPU完成五色/正方体/尺寸与四任务判断
→ round_controller一轮只判一次
→ OSD显示识别、判断、动作/不动作及理由
→ 非目标物正确SKIP
→ 20轮在10分钟内可完成
```

该版本暂不把机械臂成功抓放列为成立条件。若7个目标轮机械臂尚未接通，仍要求正确识别、正确判断并显示 `ARM_DISABLED/NOT_READY`；13个非目标轮必须正确SKIP且机械臂不动作。`54/65`仍只是全部识别/判断正确时的表内理论上限，不是成绩承诺。

### 21.2 F1不可降级的硬条件

- 正式演示处理真实物体；合成源只用于开发，不进入比赛识别判定。
- CPU必须运行在板上，PC不进入识别/控制闭环。
- 单摄必须稳定；双摄已取消，不再作为增强项进入开发。
- 目标配置不能靠重新编译硬编码，必须由板上拨码/按键锁存。
- 结果必须由OSD直观显示，UART只作镜像。
- 状态机必须具有人工确认、放弃、软复位和超时恢复。

### 21.3 F2条件升级：固定路径机械臂执行

只有以下条件全部通过，才在F1上打开机械臂动作：

1. 新180°点位表完成空载和至少5轮低速带载，无跌落和人工扶正。
2. 开发板UART端口、3.3V/5V电平、共地和接线经过文档/测量确认。
3. 1Mbps UART先通过回环和无运动/只读验证。
4. `round_controller → arm_controller` 保证每轮唯一请求，超时进入安全故障态。
5. 急停/断电方式明确，机械臂底座和场地固定。

未满足时保持F1，不用临时PC控制冒充正式闭环。
