# 0710 分赛区决赛细则对照项目优化建议

> 来源约束：[第十届全国大学生集成电路创新创业大赛“雄芯院”企业命题比赛细则](第十届集创赛分赛区决赛雄芯院企业命题比赛细则_0710.md)
> 评估日期：2026-07-12
> 评估基线：`CURRENT_STATE.md`、当前真实 CPU 源码、FPGA 预处理交接与接口草案
> 性质：规划与验收建议，不代表相关 RTL、SoC、机械臂实机闭环已经完成

## 1. 结论

当前“FPGA 视频前端/ROI/统计特征/OSD + 板上 CPU 分类、任务匹配和 myCobot 控制”的系统边界与新细则一致，无需改回纯 FPGA 识别或 PC 闭环；但工程还不能按新细则完成四项正式任务。最优先的不是继续扩展视觉 RTL，而是补齐目标输入、相对尺寸任务语义、逐轮可审计输出以及 CPU 到机械臂的闭环。

新细则明确 4 个任务、每项 5 轮，共 20 轮，实操总时限 10 分钟，理论平均预算只有 30 秒/轮，且包括摆放、识别、判断、分拣或不分拣和明确输出。任务总分为 65 分，单轮按“识别 25% + 判断 25% + 执行 50%”串行计分；识别失败会使本轮后续环节均不得分。因此系统必须把“稳定识别、明确输出、唯一动作、快速复位到下一轮”作为同等重要的主线指标。

## 2. 当前基线与细则差距

| 细则要求 | 当前真实状态 | 判定 | 直接建议 |
|---|---|---|---|
| 五种颜色均可能成为目标 | 分类器已有白/黑/红/蓝/黄，但 `task_matcher_read_target_from_fpga()` 的目标选择只编码红/蓝/黄，缺白/黑 | BLOCKER | 扩展目标输入协议，不得把 UNKNOWN 复用为白或黑 |
| 任务一：指定颜色正方体 | 匹配器可做颜色+正方体精确匹配 | PARTIAL | 补齐五色目标输入与逐轮锁存后可覆盖 |
| 任务二：正方体+颜色，混入圆柱/锥体 | 分类器和匹配器已有形状字段 | PARTIAL | 建立同尺寸三形状实物标定集，重点验证正方体拒绝圆柱/锥体 |
| 任务三：与 2cm/3cm 参考物边长差恰为 1cm | 当前只支持观测尺寸与目标尺寸精确相等 | BLOCKER | 新增任务模式 `SIZE_DELTA_EQ_10MM`，输入参考尺寸并按差值判定 |
| 任务四：与 2cm/3cm 目标物边长差≤0.5cm | 当前只支持精确相等 | BLOCKER | 新增任务模式 `SIZE_DELTA_LE_5MM`；注意一轮中可能有多个目标物 |
| 每轮必须明确输出识别、判断、执行/不执行及理由 | 当前有 UART 日志和结果回写骨架，OSD/APB/CDC 尚未闭环 | BLOCKER | 定义逐轮结果记录并同时输出到 OSD 与 UART，不能只显示 GRAB/SKIP |
| 正确识别后机械臂必须有明确且唯一响应 | `main.c` 只计算 action，仍把 ARM_STATE 写为 IDLE，未调用 `arm_controller` | BLOCKER | 把 `MATCH_ACTION_GRAB` 单次边沿触发到控制器；SKIP 必须显式输出“不动作+理由” |
| 目标位为相对起点旋转 180°±10°且臂展最大处 | 控制器已有点位/安全校验骨架，但当前无该赛场几何验收证据 | BLOCKER | 建立起点-目标点位标定规程，保存旋转角、最大臂展位置和落放高度证据 |
| 轻取轻放；跌落仅得执行环节一半分 | PC 端动作经验存在，板上 CPU 未实机闭环 | RISK | 增加夹持确认、低速下放、接近台面后释放、失败停机；优先降低跌落率 |
| 四任务总计≤10分钟 | 尚无 20 轮端到端计时证据 | BLOCKER | 以 8 分 30 秒为内部目标，预留 90 秒异常与评委交互缓冲 |
| 10分钟部署并达到一键启动 | 尚无比赛部署演练记录 | RISK | 固定平台、线缆编号、上电自检、单按钮启动、冷启动演练 |
| 全程自行录像，签字后不复议 | 尚未形成现场证据 SOP | RISK | 固定机位同时覆盖物体、机械臂、显示结果和计时画面；签字前逐项核对 |

## 3. P0：直接决定能否完成四项任务

### P0-1 重新定义“任务输入”而非继续扩展简单拨码

目标配置至少需要：

- `task_mode`：颜色正方体、形状+颜色、尺寸差=1cm、尺寸差≤0.5cm；
- `target_color`：白、黑、红、蓝、黄、无颜色约束；
- `reference_size_mm_x10`：20/25/30mm 对应的定点编码；
- `valid`、`apply/lock`、`round_reset`：确保评委确认目标后锁存，识别过程中不能被拨码抖动改变；
- 显式回读：OSD/UART 必须显示已锁存的任务、颜色、参考尺寸和比较关系。

在生成 SoC/APB 地址前，可先在 host 测试中用结构体完成语义和测试；不得把当前占位地址当成硬件事实。

### P0-2 把任务三/四实现为关系判定

不要把任务三误写成“目标尺寸=3cm”或把任务四误写成“精确匹配参考物”。建议把匹配条件统一表示为：

```text
任务三：shape == cube && abs(observed_size - reference_size) == 10mm
任务四：shape == cube && abs(observed_size - reference_size) <= 5mm
```

尺寸分类结果可继续使用 20/25/30mm 离散档位，但判定必须基于任务关系。应补齐参考尺寸为 20mm 和 30mm 的双向测试、边界 5mm/10mm、无尺寸观测、UNKNOWN、重复目标物和随机顺序用例。

### P0-3 建立“一轮一事务”的闭环状态机

推荐最小阶段：`WAIT_OBJECT -> STABLE_RECOGNITION -> RESULT_LATCHED -> DECISION_LATCHED -> EXECUTE_OR_SKIP -> ROUND_DONE -> WAIT_REMOVE`。

- 同一物体只允许产生一次机械臂动作边沿，后续稳定帧不得重复抓取。
- 目标物：识别和判断输出确认后才允许进入机械臂状态机。
- 非目标物：明确输出 `SKIP` 和不分拣依据，然后进入 `ROUND_DONE`，不能无限等待。
- 识别不确定：显示原因并保持无动作；提供“放弃本轮”人工入口以符合细则。
- 下一轮必须经过物体移除/新物体稳定检测或人工确认，避免把同一物体重复计为新一轮。

### P0-4 让现场输出直接对应评分表

每轮至少显示并记录：

```text
TASK / ROUND / OBJECT
RECOG: color, shape, size, confidence, PASS|UNSURE
DECISION: TARGET|NON_TARGET + reason
EXECUTION: GRAB|SKIP|FAULT + reason
ARM: state / completion / drop-or-fault indicator
ELAPSED: round time / total time
```

评委要求“准确无异议”输出，OSD 应为主通道，UART 和录像为证据备份。输出文字要使用中文或现场一眼可解释的固定缩写，不能依赖开发者解释寄存器数值。

### P0-5 完成 CPU→机械臂闭环，但保持机械臂安全门

当前 `main.c` 不应直接拼协议帧；应通过 `arm_controller_request_grab()` 驱动既有控制器，并由控制器更新真实 `ARM_STATE`。必须先完成 mock/host 集成测试，再确认 UART、电平、接线、急停和安全姿态，最后才做受控实机测试。PC `pymycobot` 继续只用于标定和健康证明，不得进入正式闭环。

## 4. P1：提高得分稳定性与现场效率

1. **按分数和风险组织回归集。** 四个任务都要覆盖；任务二、四各 20 分，应作为高频回归，任务一作为快速健康检查，任务三重点验证 1cm 差值关系。
2. **尺寸标定优先于更多 FPGA 特征。** 固定相机高度、物体放置区、焦距/曝光和补光，分别采集 2/2.5/3cm 多帧统计，保存混淆矩阵及最差边界；在完成真实 Debayer/板级特征采集前，不把 host 阈值视为现场有效。
3. **机械臂采用保守放置策略。** 在满足 180°±10°和最大臂展目标位置前提下，降低末段速度，接近台面后再释放，夹持后做一次有限读回确认；失败时停机并明确输出，不进行无界重试。
4. **设置 8分30秒内部时限。** 20 轮平均 25.5 秒，预留 90 秒处理评委输入、异常和任务切换。记录每轮识别、动作、复位的 P50/P95 时间。
5. **做随机顺序整场演练。** 队友模拟评委随机排序和选目标，操作者不得换序；每轮都练习“摆放-确认-输出-动作/不动作-移除”。
6. **一键启动与冷启动自检。** 自检只报告摄像头、FPGA/CPU、目标配置、UART/机械臂通信是否就绪；未就绪时禁止动作并给出明确故障码。
7. **现场证据与签字检查。** 固定录像机位，显示器画面含总计时；签字前由指定成员逐轮核对工作人员记录，签字后不再依赖复议。

## 5. 建议验收门

| Gate | 通过条件 |
|---|---|
| G0 规则单测 | 四任务×两种参考/目标输入边界、五色、三形状、三尺寸及 UNKNOWN/放弃路径全部通过 |
| G1 识别回放 | 官方规格实物或等价标定集上，输出颜色/形状/尺寸与任务判断，保存混淆矩阵 |
| G2 无机械臂闭环 | 20 轮随机顺序完整跑通，OSD/UART/计时/唯一响应一致，无重复触发 |
| G3 mock 机械臂 | GRAB/SKIP/FAULT 与控制器状态、超时、一次重试、停机路径全部可复现 |
| G4 受控实机 | 安全确认后验证轻取轻放、180°±10°、最大臂展目标点、无跌落和急停 |
| G5 全场演练 | 冷启动部署≤10分钟；四任务20轮≤8分30秒；PPT 5分钟；录像与签字检查流程完整 |

## 6. 不应改变的架构边界

- FPGA 继续负责 MIPI/视频前端、ROI、统计特征、OSD 和必要硬件加速。
- 板上 CPU 负责颜色/形状/尺寸分类、任务关系判定、参数管理、逐轮状态机和 myCobot 协议/动作控制。
- PC、外部 MCU、`pymycobot` 不进入正式识别/控制闭环。
- 未确认 SoC 生成物、APB/CDC、UART 电平/接线和机械臂安全条件前，不把草案地址或主机测试结果描述为板级闭环。
