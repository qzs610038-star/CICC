  2026-07-09 Codex bugfix (已合入):
    - [P1] ✅ match_action 编码位域映射 — task_matcher.h 逻辑码 NONE/GRAB/SKIP/ERROR
      (0/1/2/3) 不能直写 CPU_MATCH_ACTION 寄存器。手册定义该寄存器为 bitfield:
      bit[0]=match, bit[1]=grab, bit[2]=skip, bit[3]=error。
      修复: board_io.h 新增 match_action_to_hw() 静态内联函数 + MATCH_HW_* 位定义;
      board_io_write_results() 改为调用 match_action_to_hw(r->match_action) 写入。
      逻辑→硬件映射: NONE→0x00, GRAB→0x03 (match+grab), SKIP→0x05 (match+skip),
      ERROR→0x08 (error only, no match)。
      若不修: GRAB=1(0b01) 被 OSD 误读为"match", SKIP=2(0b10) 被误读为"grab",
      ERROR=3(0b11) 被误读为"match+grab"。正式联调前必修。

    - [P2] ✅ seq 失败语义修正 — board_io_commit_config() 原在超时前已 ++(*seq),
      失败时调用方 seq 已推进。改为先计算 config_seq = (*seq)+1u, 仅在
      active_seq==config_seq 成功后才 *seq = config_seq。
      同时更新 board_io.h 注释明确"成功→更新, 失败→不变"。
      重构: 抽取内部 _commit_raw() 轮询函数供 commit_config/commit_global 共用。

    - [P3] ✅ commit_global 独立于 CAM_ENABLED(0) — 全局寄存器 (ARM_STATE/
      ERROR_CODE) commit 原委托 board_io_commit_config(CAM_COMMIT_GLOBAL, seq),
      若 CAM_ENABLED(0)==0 则直接返回 -1。手册规定全局寄存器跟随 Cam0 commit
      通道, 但这是硬件通道选择, 不应受 CAM_ENABLED 视频链路使能开关影响。
      修复: board_io_commit_global() 直接调用 _commit_raw(), 跳过 CAM_ENABLED 检查。
      board_io.h CAM_COMMIT_GLOBAL 注释同步说明此独立性。

    - [P3] ✅ frame_id 二次确认 — board_io_read_features() 读完 LIVE_* 后重读
      SYS_STATUS, 确认 frame_id 未变且 valid 仍为 1。当前手册 v2 约定"FPGA 在
      ack 前不覆盖快照", 此检查属防御性措施。若 RTL 未遵守锁存约定, 自动丢弃
      不一致数据并返回 -1, 调用方重试。

    - 测试: 全部 180/180 单测通过 (classifier 31 + param_table 76 + matcher 73),
      gcc 14.2.0 x86-64. board_io.c 独立编译 0 error (仅占位符 warning)。

  主循环伪代码:

    void main(void) {
        // 1. 上电握手
        if (board_io_validate() != 0) { halt_with_error(ERR_NO_FPGA); }

        // 2. 初始化
        param_table_init();              // 加载分类器配置
        mf_filter_t filt_cam0, filt_cam1;
        mf_filter_reset(&filt_cam0);
        mf_filter_reset(&filt_cam1);
        uint16_t seq_cam0 = 0, seq_cam1 = 0;
        const classifier_cfg_t *cfg = param_table_get();

        // 3. 写入初始配置到两路 staging + commit
        board_io_write_config(0, ...);
        board_io_write_config(1, ...);
        board_io_commit_config(0, &seq_cam0);
        board_io_commit_config(1, &seq_cam1);

        // 4. 主循环
        while (1) {
            board_io_heartbeat();

            // ---- 处理 Cam0 ----
            feature_snapshot_t snap0;
            uint16_t obj_cx = 0, obj_cy = 0;   /* 物块 bbox 中心（俯视） */
            if (board_io_read_features(0, &snap0) == 0) {
                vision_result_t r0 = classify_frame(&snap0, 0, cfg);
                vision_result_t s0 = mf_filter_update(&filt_cam0, &r0, cfg);
                obj_cx = (uint16_t)(snap0.center & 0xFFFF);       /* [15:0]X_CEN */
                obj_cy = (uint16_t)((snap0.center >> 16) & 0xFFFF); /* [31:16]Y_CEN */
                board_io_ack_frame(0, snap0.frame_id);
                // 先回写分类结果（match_action 先填 0，等融合决策后两路统一更新）
                result_writeback_t wb0;
                board_io_build_writeback(s0.color_id, s0.shape_id,
                                          s0.size_cm_x10, 0, &snap0, &wb0);
                board_io_write_results(0, &wb0);
                board_io_commit_results(0, &seq_cam0);
            }

            // ---- 处理 Cam1 ----
            feature_snapshot_t snap1;
            if (board_io_read_features(1, &snap1) == 0) {
                vision_result_t r1 = classify_frame(&snap1, 1, cfg);
                vision_result_t s1 = mf_filter_update(&filt_cam1, &r1, cfg);
                board_io_ack_frame(1, snap1.frame_id);
                // 先回写分类结果（match_action 先填 0，等融合决策后两路统一更新）
                result_writeback_t wb1;
                board_io_build_writeback(s1.color_id, s1.shape_id,
                                          s1.size_cm_x10, 0, &snap1, &wb1);
                board_io_write_results(1, &wb1);
                board_io_commit_results(1, &seq_cam1);
            }

            // ---- 融合决策 ----
            vision_result_t fused = fuse_results(
                &filt_cam0.stable, &filt_cam1.stable, cfg);
            // 2026-07-09 用户决策:
            //   允许单路稳定时输出 GRAB, 但若目标含尺寸要求(size_sel!=00),
            //   必须 Cam1(水平/侧面)稳定可用, 因为尺寸只看 Cam1 height_px。
            //   仅 Cam0 稳定时只能处理尺寸通配目标。
            //   UNKNOWN 在正式主线中输出 NONE; 调试模式可映射为 ERROR 便于 OSD 看问题。

            // ---- 目标输入 ----
            // 从 FPGA TARGET_SEL 寄存器读取：color_sel[1:0] + size_sel[1:0] + target_valid
            // shape 固定为 SHAPE_CUBE（识别侧只抓正方体）。
            // target_valid=0 时自动清空目标，evaluate() 返回 NONE。
            // TARGET_SEL_AVAILABLE=0 时正式主线也清空目标; 手动目标仅限显式调试模式。
            task_matcher_read_target_from_fpga();

            // ---- 任务匹配 / 识别侧输出 ----
            // obj_cx/obj_cy 来自 Cam0 快照的 bbox 中心（见上方 snap0.center 解包）
            uint8_t action = task_matcher_evaluate(&fused, obj_cx, obj_cy);
            // 输出给队友/系统集成:
            //   fused.color_id, fused.shape_id, fused.size_cm_x10, action
            //   action==GRAB 仅授权固定 P_pick 抓取序列, 不携带视觉抓取坐标。
            // 最终 match_action 首版推荐 Cam0/Cam1 两路都写同一个 action,
            // 这样 HDMI/OSD 切任一通道都能看到一致的抓取/跳过/报错状态。
            // 抓取中心点只用于 OSD/日志/偏差检查, 默认不交付 arm_controller:
            //   uint16_t cx, cy;
            //   if (action == MATCH_ACTION_GRAB &&
            //       task_matcher_get_grab_coord(&cx, &cy) == 0) {
            //       // log/debug only; do not use as real-time arm coordinate
            //   }

            // ---- 机械臂集成边界 ----
            // 当前 main.c 尚未调用 arm_controller_request_grab()/arm_controller_tick()。
            // action==GRAB 只写 OSD/日志/授权状态，不会直接驱动机械臂。
            // 后续必须先完成四任务事务锁和板上 UART 驱动，再接入非阻塞 arm_controller。
        }
    }
