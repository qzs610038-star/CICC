  P0 阻塞修正（先修或至少先写 failing test/Review Packet）:

    A. `main.c` error_code 吞错 bug
       - 当前风险: 本轮 Cam0/Cam1 的 `board_io_commit_results()` 失败会设置
         `err_code = ERR_COMMIT_TIMEOUT`，但随后 `board_io_commit_global()` 若成功，
         当前代码会把 `err_code` 清为 0，导致本轮错误被静默吞掉。
       - 需要 Claude 在实现前给出最小修复方案，建议二选一:
         1) 本轮局部错误码:
            `uint16_t loop_err = 0;`
            每次 commit_results 失败只设置 `loop_err`；
            在 `board_io_write_global_state(ARM_STATE_IDLE, loop_err)` 之前完成所有错误收集；
            `commit_global` 失败只能影响下一轮或单独 latch，不能倒写吞掉本轮错误。
         2) latch 型错误码:
            有新错误时置位，只有明确 reset/ack/健康检查通过后清零；
            不能因为一次 `commit_global` 成功自动清除历史错误。
       - 完成标准: 增加 mock/host 层测试或可审查伪测试，覆盖
         `commit_results fail + commit_global success` 时 ERROR_CODE 仍非 0。

    B. 四任务判定接口必须定签名，不能自由发挥
       - `task_target_t` 建议扩展为:

         typedef enum {
             TASK_MODE_NONE = 0,
             TASK_MODE_1    = 1,
             TASK_MODE_2    = 2,
             TASK_MODE_3    = 3,
             TASK_MODE_4    = 4
         } task_mode_t;

         typedef enum {
             ROUND_IDLE = 0,
             ROUND_TARGET_LOCKED,
             ROUND_GRAB_REQUESTED,
             ROUND_DONE
         } round_state_t;

         typedef struct {
             uint8_t target_color;          /* COLOR_WHITE/BLACK/RED/BLUE/YELLOW/UNKNOWN */
             uint8_t target_shape;          /* 首版固定 SHAPE_CUBE */
             uint8_t target_size_cm_x10;    /* 20/25/30; 0=通配或本任务不用 */
             uint8_t reference_size_cm_x10; /* 任务三参照尺寸; 0=未锁定 */
             uint8_t task_mode;             /* TASK_MODE_1..4 */
             uint8_t round_state;           /* ROUND_* 防重复触发 */
         } task_target_t;

       - `task_matcher_evaluate()` 内部必须按 task_mode 分派:

         MODE_1   -> match_color_cube()（同尺寸正方体池，目标输入为颜色）
         MODE_2   -> match_color_shape()（混合形状池，尺寸通配）
         MODE_3   -> match_relative_delta_10mm()
         MODE_4   -> match_relative_delta_5mm()

       - 任务三临时规则（待官方/用户确认前不得写死到散落常量）:
         `abs(obs.size_cm_x10 - reference_size_cm_x10) == TASK3_SIZE_DELTA_CM_X10`
         其中 `TASK3_SIZE_DELTA_CM_X10 = 10`，因为 `cm_x10` 单位中 10 等于 10mm/1cm。
         当前分类输出已经是 20/25/30 的离散尺寸，首版按“精确等于 10mm 差值”处理；
         若后续改成“约等于”，必须只改统一 tolerance 常量和测试。
       - 任务四临时规则:
         `abs(obs.size_cm_x10 - target_size_cm_x10) <= TASK4_SIZE_DELTA_MAX_CM_X10`
         其中 `TASK4_SIZE_DELTA_MAX_CM_X10 = 5`，即边长差不超过 5mm/0.5cm。
       - reference_size 来源（首版 Host-only）:
         先由测试或显式 API 写入 `reference_size_cm_x10`，模拟“第一轮/参照物已测得”；
         在 FPGA `TARGET_SEL` 未扩展前，不从拨码读取 reference_size，不伪造硬件字段。

    C. 五色目标与 2-bit `color_sel` 冲突
       - 旧 `TARGET_SEL.color_sel[1:0]` 只有 4 个编码，且已经定义为:
           00=通配, 01=红, 10=蓝, 11=黄
         它无法同时表示 WHITE/BLACK/RED/BLUE/YELLOW 五色。
       - 四任务 Host 层必须先支持五色目标；但正式硬件输入不能继续沿用旧
         2-bit `color_sel` 作为五色来源。
       - 默认建议的下一版硬件/寄存器契约:

         bit [2:0] target_color_sel:
             000 = ANY
             001 = WHITE
             010 = BLACK
             011 = RED
             100 = BLUE
             101 = YELLOW
             110/111 = RESERVED
         bit [4:3] target_size_sel:
             00 = ANY
             01 = 20mm
             10 = 25mm
