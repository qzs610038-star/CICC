## 2. 调试故障与技术原因深度分析

在推进 A0 $\rightarrow$ A3 的过程中，共发现并闭环了以下三处关键故障：

### 故障一：`drop_hover -> home_ready` 过渡安全门拦截
* **现象**：在安全门校验阶段报错：`回零过渡单轴变化过大 (arm_max_delta=110.8 > 90.0)`，程序直接熔断拦截。
* **原因**：大臂旋转 180° 后，示教 `home_ready` 中转点时发生了**异侧翻面（姿态向相反方向折叠）**。J3 关节在前一点为强负角（如 $-100^\circ$），在后一点被拉到正角（如 $+10^\circ$），导致过渡时小臂必须经历一次剧烈的强行空翻。
* **解决**：提示现场进行规范化示教（覆盖原预设）。记录 `home_ready` 时，顺着 `drop_hover` 的折叠朝向让大臂和小臂顺势微幅收回，将 J3 关节的差值成功控制在 $76.3^\circ$（符合 $90.0^\circ$ 安全限值内）。

### 故障二：`drop_hover` 空中长距离运动未到位死区卡顿
* **现象**：长距离移动 180° 到达 `drop_hover` 后，实际关节到位极好（最大误差仅 $2.02^\circ$），但由于固件到位算法判定未收敛，`mc.sync_send_angles` 在 Python 层持续阻塞 20 秒直到超时返回 `0`。
* **原因**：固件到位死区与大臂旋转摩擦力矩叠加，导致微小偏差无法收敛，卡死在官方阻塞函数内。
* **解决**：在 [teach_replay_pick_return_ready.py](file:///d:/%E7%AC%AC%E5%8D%81%E5%B1%8A%E9%9B%86%E5%88%9B%E8%B5%9B-%E9%9B%84%E8%8A%AF%E9%99%A2%E6%9D%90%E6%96%99/mycobot_pc_tests/teach_replay_pick_return_ready.py) 脚本的 `checked_sync_angles`（长距离同步回放接口）内部，**增加了软到位（`allow_soft_success`）判断**。一旦发生超时，只要最大轴误差在 $3.0^\circ$ 的推荐软容差内，即可宣布软通过，继续运行而不抛异常熔断。

### 故障三：释放点逗留时间过长，动作效率偏低
* **现象**：机械臂运动在释放点 `drop` 上空停滞，且松爪放置物块耗时偏长。
* **原因**：
  1. 下探 `drop` 处受负载惯性影响大，大臂下沉使固件收敛缓慢；且未开启软到位，导致程序不得不白白消耗几秒等待完全到位。
  2. 夹爪开合处于开环控制，原设定的 `GRIPPER_TIMEOUT` 延时为 1.2 秒，而实际松爪只需要约 0.6 秒。
* **解决与极限压缩**：对脚本控制参数和时序进行了以下全面调优：
  * **极限缩减死区停等**：将长距离回放超时 `ANG_REPLAY_TIMEOUT` 从 20s 极限压缩至 **`6.5s`**（大臂物理旋转实际需要 4.5s 左右）。即使固件不收敛，最多等 2s 就会自动通过。
  * **缩短短动作卡顿**：将短距离运动（下探和抬起）的超时限制统一由 10s/15s 极限压缩至 **`4.0s`**。
  * **动作提速**：将长距离速度 `ANG_REPLAY_SPEED` 提升至 **40%**；下探速度提升至 **18%**；抬起速度提升至 **25%**。
  * **夹爪时序优化**：夹爪延时 `GRIPPER_TIMEOUT` 缩短至 **0.8s**。
  * **全面覆盖软到位**：在步骤 3（下探 `pick`）与步骤 7（下探 `drop`）中均开启 `allow_soft_success=True`，彻底抹平所有动作的死区停顿。

## 4. 后续移植与板上开发建议（G4-G11）
虽然 PC 端已完全通过，但这仅用于 PC 离线示教与动作路径的探索。板上 CPU（RISC-V 异构控制）的开发依然需要遵循以下硬性规范：
1. **点位数据提取**：本实验中生成的 `route_a_20260714_2000` 点位表现非常优秀，可在下一步将对应的 6 轴角度硬编码存入板上 CPU 的点表结构体中。
2. **安全超时与到位移植**：在板上实现 UART 通信读取机械臂关节角时，必须同样实现**软到位判定机制**（如当读取到的各轴脉冲在目标值一定误差范围内时即提前下发下一阶段指令），严禁直接等待机械臂固件的"到位状态寄存器（is_in_position）"，否则必然会在板端重新引发同样的"死区停等超时"。
3. **安全防碰撞熔断**：在板上 CPU 的状态机中，必须基于我们刚才测试的超时极限（如长距离 6.5s，短距离 4s），如果读取到的状态在指定时间内未接近到位，必须强行进入 `ROUND_STATE_ARM_FAULT`，并物理切断机械臂动作，以防碰撞损坏。

## 5. 已知风险点（板上首测前必读）

本次 3 轮抓放虽全部通过，但原始日志（`auto_run_20260714_203359.log`）暴露了以下系统性风险，直接复用当前代码作为板上首测基准前必须知晓：

### 风险一：drop_hover 长距离过渡固件系统性不收敛（最高风险）

**原始日志事实**：
- 第 1/3 轮 step 6：`drop_hover 运动同步返回 0 (未收敛或超时)` → `[软通过] 最大轴误差 2.02°`
- 第 2/3 轮 step 6：同上，2.02°
- 第 3/3 轮 step 6：同上，2.02°

**问题本质**：3/3 轮的 drop_hover 长距离过渡，固件 is_in_position 判定均未收敛（返回 0）。当前能跑通完全依赖 V2.10 新增的兜底分支：`sync_send_angles 返回 0 → 读实际角度 → max_diff ≤ SOFT_ANGLE_SUCCESS_TOL(3°) → 软通过 return True`。

**板上移植影响**：
- 板上 RISC-V 若直接复用这套逻辑，必须同时实现 `get_angles` 读回 + 3° 容差判断
- 若板端 UART 驱动无法稳定读回 6 轴角度，则该兜底失效，会卡死在等待固件收敛
- 该点位处于固件收敛边界，机械装配微变可能导致从"软通过"退化为"硬熔断"

### 风险二：夹爪完全开环，无任何到位反馈

**原始日志事实**：
```
-> [GRIP_UNVERIFIED] 当前库无 get_gripper_value 反馈接口，使用开环定时等待。
```
出现 9 次（3 轮 × 每轮 3 次夹爪动作：张开准备、闭合抓取、张开放置）。

**问题本质**：当前 pymycobot 库版本无 `get_gripper_value` 反馈接口，夹爪控制为纯开环定时等待（GRIPPER_TIMEOUT=0.8s）。物块尺寸/重量变化时 0.8s 可能不够；脚本无法知道物块是否真正夹住。

**板上移植影响**：
- 0x66/0x67 无 ACK，不能等待固件返回
- 必须用 0x69（IS_GRIPPER_MOVING）轮询至停止 + 0x65（GET_GRIPPER_VALUE）读位置窗口确认夹持成功
- 位置读回只能证明夹爪闭合位置，不能单独证明夹持力或物体未滑落

### 风险三：样本量小，稳定性未充分验证

**问题本质**：仅 3 轮成功，不足以证明长期稳定性。drop_hover 每轮都靠软通过说明该点位处于固件收敛边界。

**板上移植影响**：
- 板上首测时应准备多轮连续运行（≥5 轮）观察退化趋势
- 若 drop_hover 从"软通过"退化为"硬熔断"，需重新示教该点位或调整路径

## 6. 安全防护盘点（板上首测可酌情去除/保留）

当前 `teach_replay_pick_return_ready.py` 包含多层安全防护。根据用户决策——"实际观察抓取效果比较可观，仍把当前代码作为首次上板尝试代码，只是标注好风险点；如果后续上板时当前代码过多安全防护导致卡死，可以酌情去除安全防护，主要依赖安全员快速物理断电"——以下盘点哪些防护可去除、哪些底线不能去除。

### 6.1 可酌情去除的安全防护（卡死时可砍）

| 防护机制 | 位置 | 去除影响 | 建议 |
|---|---|---|---|
| **坐标一致性校验 verify_coords_near** | auto_phase_v2 step 2/3/5/6/7/9 | 仅丢失到位后的只读复核，不影响运动 | ✅ 可去除。SKIP_COORD_VERIFY_ON_STRICT_PASS=True 已部分跳过；板上可直接不实现 |
| **短距离点对关节连续性预校验 validate_short_angle_pair** | auto_phase_v2 step 0 | 丢失 IK 分支跳变拦截 | ⚠️ 谨慎去除。若点位固定且已实测验证过，可去除；否则保留 |
| **home_ready 推荐余量门 HOME_READY_TARGET_ARM_MAX=40** | record_return_ready_point | 丢失示教阶段的提前预警 | ✅ 可去除。这只是推荐门，硬门 ARM_MAX_DIFF_SAFE=45 仍在 |
| **半径分区诊断 print_radius_diagnostic** | record_teach_point | 丢失带载半径分级提示 | ✅ 可去除。纯诊断打印，不影响逻辑 |
| **power_on 后读数稳定等待 POWER_ON_SETTLE=1.5s** | prepare_phase | 丢失上电暂态过滤 | ⚠️ 谨慎去除。若板端读数稳定可缩短；完全去除可能导致首帧读数异常 |
| **连续两次读数稳定性判断 ANG_STABLE_TOL/COORD_STABLE_TOL** | get_filtered_angles/get_filtered_coords | 丢失读数抖动过滤 | ⚠️ 谨慎去除。若板端 UART 稳定可放宽；完全去除可能读到运动中瞬态值 |

### 6.2 不能去除的底线防护（去除即失去安全边界）

| 防护机制 | 位置 | 去除后果 | 底线理由 |
|---|---|---|---|
| **大臂安全门 ARM_MAX_DIFF_SAFE=45** | safe_return_home | 去除后大偏差时直接自动回零，产生大范围弧线扫动 | §13.2：大臂 1-5 轴偏差 >45° 时禁止自动回零，必须人工扶正 |
| **物理臂展硬限 R_MAX=280** | is_safe_coord | 去除后目标位置可能超出最大臂展，撞限位 | 所有点的物理硬限，不可放宽 |
| **急停优先级：物理断电 > 软件 stop** | 全局 | 去除后失去最后一道防线 | 安全员手持 12V 插头，≤2 秒断电；这是用户明确指定的主要安全依赖 |
| **软到位容差 SOFT_ANGLE_SUCCESS_TOL=3°** | checked_sync_angles V2.10 兜底 | 去除后 drop_hover 每轮硬熔断，流程无法走通 | 这是当前代码能跑通的核心兜底，板上移植必须保留 |
| **关节角合法性校验 valid_angles** | record_teach_point | 去除后可能保存非法姿态 | 数值型 + 有限 + [-180,180]，基础输入校验 |
| **KeyboardInterrupt 立即 release_all_servos** | main except | 去除后 Ctrl+C 急停时舵机不掉电 | 急停语义，不可削弱 |

### 6.3 板上首测的建议策略

1. **保留全部 6.2 底线防护**，特别是软到位容差兜底（风险一的直接对策）。
2. **若板端卡死**，按 6.1 表从上往下逐项去除，每去除一项做一次完整 3 轮抓放验证。
3. **夹爪控制**（风险二）必须从开环改为 0x69+0x65 确认，不能直接复用 0.8s 定时等待。
4. **drop_hover 点位**（风险一）若板端无法稳定读回角度做软通过兜底，考虑：
   - 重新示教 drop_hover 到固件能收敛的位置
   - 或拆分为两个中间过渡点，降低单段长距离收敛压力
5. **安全员物理断电**是用户明确指定的主要安全依赖，软件层急停仅为辅助。
