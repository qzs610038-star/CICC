#### 1.2 已确认事实

- 本轮最后一个示教姿态是 `drop`，关节角为 `[-73.03, -73.74, -58.71, 49.04, 1.84, 56.95]`，坐标为 `[15.7, -263.4, 68.8, -178.08, 6.62, 140.23]`。
- 通电后 `safe_return_home()` 读取到最大关节偏差 `73.7` 度，因此进入“大偏差回零保护”分支。
- 保护目标打印为 `Z=180.0`，说明脚本把当前 `drop` 坐标的 Z 从 `68.8` 改成了 `180.0`，再调用 `sync_send_coords(protect_coords, 30, 0, timeout=10)`。
- 保护动作返回失败或超时，脚本拒绝继续关节回零，并提示用户扶稳后释放舵机。

#### 1.3 原因分析

此处失败不能简单归因于“直线模式 IK 奇异”，因为新脚本确实已经把保护拉升的 `mode` 改成了 `0`。但 `mode=0` 只是关节空间插值，不等于完全摆脱笛卡尔坐标目标。

当前代码仍在构造 `protect_coords`：保持当前 X/Y/RX/RY/RZ 不变，只把 Z 改为 `180.0`。这类目标仍需底层 IK 解算，并且 `sync_send_coords()` 仍以坐标到位作为成功条件。对于 `Y=-263.4mm`、末端姿态接近翻腕的远端放置点，`[15.7, -263.4, 180.0, -178.08, 6.62, 140.23]` 可能不可达、接近关节限位、或可达但无法满足固件坐标到位判定，因此返回 `0`。

修正结论：`safe_return_home()` 的大偏差分支不应继续自动构造笛卡尔保护拉升目标。更稳妥的策略是要求用户手动扶到预回零姿态，或在示教阶段额外记录一个 `safe_transit_angles/home_ready_angles`，运行时用 `sync_send_angles()` 做关节空间中转。

#### 2.2 已确认事实

- 第二轮最后一个示教姿态是 `drop`，关节角为 `[-75.49, -72.94, -54.58, 41.39, 0.08, 58.88]`，坐标为 `[3.8, -267.1, 72.8, -178.22, 3.44, 135.67]`。
- 通电后脚本打印 `max_diff=78.9`，说明程序读取到的当前关节角仍然距离 `[0,0,0,0,0,0]` 很远。
- 随后 `get_filtered_coords()` 连续 6 次读取到 `Z=401.7`，但这些读数被 `is_safe_coord()` 的 `Z_MAX=280.0` 拦截，最终返回 `None`。
- 因 `coords is None`，`safe_return_home()` 拒绝执行后续保护拉升和关节回零。

#### 2.3 原因分析

这一轮包含两个独立问题。

第一，`get_filtered_coords()` 误用了工作区安全框。它的职责应是过滤串口异常、非数字、NaN/Inf 和短时间抖动；但当前实现直接调用 `is_safe_coord(coords)`。`is_safe_coord()` 的 `Z_MAX=280.0` 是抓取/放置工作空间上限，不是机械臂全局有效坐标上限。直立或接近直立姿态读到 `Z=401.7mm` 很可能是正常物理坐标，不应被当作无效读数。

第二，原始日志证明“人工扶正到接近直立”与程序读取 `max_diff=78.9` 之间存在矛盾。也就是说，当前还不能断言第二轮已经真的处于程序定义的零位附近。可能情况包括：

- 人工观察的“直立安全姿态”并不等于脚本硬编码的 `[0,0,0,0,0,0]`。
- 用户是在释放舵机后扶到较高姿态，但某些关节角实际仍远离 0 度。
- `get_filtered_angles()` 只接受首个合法角度，没有做双读稳定校验；若读到瞬时但数值范围合法的异常角，也会触发大偏差分支。
- 机械臂上电锁定后出现姿态回弹或用户松手时姿态变化，导致按 Enter 时的姿态和肉眼扶正时不一致。

修正结论：需要先拆分 `is_valid_coord_reading()` 与 `is_safe_work_coord()`；同时在回零前打印当前 `angles`，并确认本机 myCobot 的真实“安全零位/直立姿态”到底对应哪组角度，而不是继续默认 `[0,0,0,0,0,0]`。

### 3. 用户补充观察与复核修正

用户对第三次试运行补充确认如下：

1. 第二次实验中，录完四个点后，用户确实已经把机械臂手动扶到了接近零位。
2. 扶正时电机仍处于释放状态；随后用户敲击 Enter，脚本恢复上电，电机抱紧。
3. 第一次实验中的“抬高保护动作失败”几乎立刻报错，不是等待完整 timeout 后才失败。
4. 用户肉眼认为的接近零位姿态为：夹爪尖端朝前。

这些补充使本轮判断进一步收紧：

- 第二次实验不应再解释为“用户可能没有扶正”。更准确的表述是：**释放状态下肉眼扶到接近零位后，脚本上电读取到的关节角仍与硬编码 `[0,0,0,0,0,0]` 相差 `78.9` 度**。
- 这强烈提示当前脚本里的 `HOME_ANGLES = [0,0,0,0,0,0]` 未必等于本机实物上“夹爪尖端朝前”的安全零位，或者上电抱紧瞬间发生了姿态回弹/关节读数变化。
- 第一次实验几乎立刻报错，说明 `sync_send_coords(protect_coords, 30, 0, timeout=10)` 很可能不是单纯“走得慢导致超时”，而是目标坐标被底层快速判定不可达、IK 解算失败、关节限位/姿态约束失败，或坐标到位判定立即失败。继续靠延长 timeout 不能解决根因。
- `Z=401.7` 被拦截仍是确定的软件逻辑错误：`get_filtered_coords()` 不应把直立高位姿态当成非法读数。

因此，后续修复优先级应调整为：

1. 先运行只读/低风险的零位标定辅助脚本，记录“夹爪尖端朝前”时真实 `get_angles()` 和 `get_coords()`，不要继续假定 `[0,0,0,0,0,0]`。
2. 在 `safe_return_home()` 中打印上电后的 `angles`、`diffs`、`coords`，确认 Enter 上电抱紧后是否发生姿态回弹。
3. 删除或禁用大偏差分支里的自动 `protect_coords` 拉升，避免从释放示教姿态直接构造笛卡尔保护目标。
4. 拆分坐标读数有效性过滤和工作区安全拦截。

### 4. 针对本轮日志的代码修复建议

1. `get_filtered_coords()` 改为只做“读数有效性过滤”，不要调用 `is_safe_coord()`。

## 第四次只读测试（2026-07-05 记录“夹爪尖端朝前”的安全零位读数）

在人工将机械臂扶正至“夹爪尖端朝前”的直立姿态后，使用只读检测脚本连接 `COM10` 串口读取机械臂的传感器读数。测试结果极其稳定，10 次连续采样的读数完全一致。

### 1. 物理读数记录

*   **当前关节角度 (get_angles())**：`[-10.81, 2.46, 1.49, -8.17, 2.28, 3.07]`
*   **当前空间坐标 (get_coords())**：`[27.3, -67.9, 416.9, -94.22, 3.23, -98.75]`

### 2. 结论与设计决策

#### 2.1 HOME_ANGLES 设定决策
本机实测“夹爪尖端朝前”的物理姿态下，关节角 `get_angles()` 与理论硬编码零位 `[0, 0, 0, 0, 0, 0]` 的各关节最大绝对偏差为 **`10.81` 度**（发生在第 1 关节），其余各关节偏差均在 1.5° ~ 8.2° 之间。
*   该物理偏差远低于安全回零的阈值（45度）。若 `safe_return_home()` 在上电稳定后读到这组角度，应不会触发大偏差保护分支，也不会产生从远端姿态直接大范围回扫的问题。
*   因此，**当前没有必要将代码中的 `HOME_ANGLES` 从 `[0, 0, 0, 0, 0, 0]` 修改为其他非零实测值**。理论零位仍可作为回零目标，但实际动作仍应保持低速、空载、手在急停旁验证。

#### 2.2 Z_MAX 拦截逻辑验证
在直立状态下，物理测量得到的 Z 坐标为 **`416.9` mm**。
*   此数据直接验证了之前对“Z=401.7 被拦截”的分析：在机械臂直立或接近直立的安全姿态下，由于臂展全部伸展，其实际 Z 轴高度必然会在 400mm 左右，这已经严重超出了抓取工作空间的 `Z_MAX = 280.0` 限制。
*   这进一步证明了**必须将 `get_filtered_coords()` 中的坐标过滤逻辑拆分**：即 `get_filtered_coords()` 应该只进行“串口数据有效性/数值合法性过滤”（如检查 `isfinite()`，以及宽松的物理机械边界如 Z 在 `[-500, 500]`），而不应在此时调用基于抓取工作区限制的 `is_safe_coord()`。`is_safe_coord()` 应当仅仅在示教点保存或笛卡尔直线运动规划时作为业务级安全边界进行调用。

#### 2.3 与第三次试运行异常的对照解释

第四次只读测试显示，“夹爪尖端朝前”的真实安全零位角度最大偏差只有 `10.81` 度。因此，第三次第二轮中 `safe_return_home()` 打印 `max_diff=78.9` 的现象，不再优先解释为 `HOME_ANGLES` 定义错误，而更可能来自以下链路问题：

*   释放舵机后手动扶正、随后上电抱紧的瞬间，`get_angles()` 读到了暂态值或旧姿态残留值。
*   `get_filtered_angles()` 当前只接受首个合法读数，没有要求连续两次角度稳定；只要读数在 `[-180, 180]` 内，就会被当作可信当前姿态。
*   `get_coords()` 同时读到 `Z=401.7`，与第四次 `Z=416.9` 高度一致，说明空间坐标已经接近直立高位；这与 `max_diff=78.9` 之间存在“坐标像零位、角度不像零位”的读数不一致。

后续修复除拆分 `get_filtered_coords()` 外，还应在 `power_on()` 后增加稳定等待，并让 `get_filtered_angles()` 做连续读数一致性校验。若坐标显示处于高位直立、但角度读数突然显示大偏差，应打印完整 `angles/coords` 并重试，而不是立刻进入笛卡尔保护拉升。
