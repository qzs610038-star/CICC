## 4. 异常根因分析

### 4.1 诊断数据揭示的核心事实

诊断数据完全推翻了"IK 解算失败"假设（run-5 根因），也推翻了"通信丢帧"猜想：

- 机械臂 **确实运动了**，6 个关节全部接近目标（最大偏差 J2=2.19°）
- 运动方向正确（J2 从 -75.49° 回到 -65.83°，只差 2.19° 到目标 -63.63°）
- 末端 Z 爬到 92.0mm，距目标 104.6mm 仅差 12.6mm
- **问题不是"动不了"，而是"快到了但没在规定时间内完全到位"**

### 4.2 根因确证：抗重力收敛与到位检测不匹配

`sync_send_angles` 的底层到位判断依赖固件 `is_in_position` 轮询。固件判定"到位"的精度门限较严格（可能约 ±1°），而：

- **下行**（step 3, pick_hover→pick）：J2 从 -63.63° → -75.49°（顺重力加速），末段 PID 易收敛，快于内部轮询窗口。
- **上行**（step 5, pick→pick_hover）：J2 从 -75.49° → -63.63°（抗重力爬升），末段 PID 舵机在负载下接近目标时收敛变慢。2.19° 的残余偏差说明 PID 在末端趋近阶段遇到了反重力阻力，`is_in_position` 在 10s 窗口内从未判定为 True。

### 4.3 与 run-6 对比

| 项目 | run-6 | run-7 |
|------|-------|-------|
| pick_hover 示教位置 | R=267.5mm (J2=-56.6) | R=260.7mm (J2=-63.6) |
| 下行 J2 变化 | 13.53° | 11.86° |
| 上行 J2 变化 | 13.53° | 11.86° |
| 到 J2 目标差 | 未知（无诊断） | 2.19° |
| 结果 | 返回 0 | 返回 0，且诊断明确剩余 2.19° |

示教位置更优后（pick_hover 臂展从 267.5→260.7mm，关节变化从 15.4→11.9°），**下行精度改善但上行模式完全一致**——说明这不是示教位置微调能解决的问题。

### 4.4 用户假设重新回应

上一轮（run-6）将"人工扶正影响"判断为低概率。本轮数据进一步排除此假设：step 2/3 的到位精度（5.7mm / 2.6mm）是迄今为止最优的，说明扶正·回零·回放链路完全正常。问题纯粹出在 **上行抗重力方向** 的到位收敛速度与 10s 超时的匹配关系上。

## 5. 结论与修复方向

### 5.1 根因定论

> **"`sync_send_angles` 上行路径的到位判定超时"**
>
> 机械臂下行（重力辅助）可在 10s 内完成并触发 `is_in_position=True`，但上行（抗重力）路径的 PID 收敛末段超过 10s 窗口，导致固件返回 0，上位机熔断。

### 5.2 可靠复现性

该故障已在 run-6 和 run-7 中以 **完全相同的步骤（step 5, pick→pick_hover）** 连续复现两次，复现率 100%。这已排除随机串口故障，确认是系统性问题。

### 5.3 修复方向

1. **增加上行超时窗口**：将 `SHORT_ANGLE_TIMEOUT` 从 10s 增至 20–30s。
2. **区分上下行速度**：下行保持 12，上行提高至 20+。
3. **到位容忍门限**：若 `sync_send_angles` 返回 0 但实际关节角与目标偏差 <3°，可视为到位成功（需增加 `is_in_position` 替代判断）。
4. **非对称速度参数**：hover→down 用较低速度（安全下探），down→hover 用较高速度（快速抬升）。

### 5.4 物理观察

与第六次实验一致（用户注明），无额外观察补充。
