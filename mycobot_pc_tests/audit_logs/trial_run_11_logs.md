## 5. 物理观察与用户反馈

### 5.1 两轮带载均顺利完成

- Run A（2cm 正方体）：完整抓取→放置流程跑通，物理夹抓可靠。
- Run B（3cm 正方体）：完整抓取→放置流程跑通，虽然 R 处于边缘风险区（260~274mm），仍成功夹取 3cm 正方体。

### 5.2 问题 1：step 5-6 等待时间较长

**现象**：step 5（pick→pick_hover）上行后，脚本等待约 25s 超时，然后触发软通过诊断。step 6（pick_hover→drop_hover）长距离回放也有明显等待。

**根因**：
- step 5 `SHORT_UP_TIMEOUT=25s` 是为上行抗重力动作预留的宽松窗口（run-7 确证固态）。但物理到位约在 5~8s，剩余 15s+ 花在等待固件 `is_in_position` 判到位上。
- 软通过诊断本身还要额外时间（get_filtered_angles × 2 + get_coords + 计算）。

**建议**：将上行超时从 25s 缩短至 15s，让软通过更早触发。或增加"软通过优先"模式：一旦 sync_send_angles 返回 0 且角度偏差 ≤3°，立即停止等待进入诊断，不耗完完整超时。

### 5.3 问题 2：约 1cm 的到位误差

**现象**：两轮各步骤的坐标校验 delta_xyz 普遍在 7~13mm，最大达 16.2mm（Run B step 9）。对于夹爪最大张度而言，3cm 正方体接近夹爪极限，1cm 误差可能使夹取位置偏移严重，导致抓取失败。

**数据统计**：

| 动作类型 | 平均 delta_xyz | 最大 delta_xyz | 样本数 |
|----------|---------------|---------------|--------|
| 长距离（sync_send_angles 正常返回） | 7.1mm | 8.9mm | 2 |
| 短距离下行（speed=12，重力辅助） | 5.1mm | 6.3mm | 2 |
| 短距离上行软通过（speed=16） | 14.5mm | 16.2mm | 2 |

**根因**：软通过场景下固件 `is_in_position` 在 ~2° 偏差处判超时返回 0，诊断读取的实际关节角 max_err=2.0~2.5°，映射到末端位置就是 10~16mm 误差。

**建议**：
1. **提高上行速度**：SHORT_UP_SPEED 从 16 逐步试探 20→25，减少到位前的残余偏差
2. **加入第 2 轮微调**：软通过后对残余偏差 <3° 的关节做一次短时间微调（而非直接放行），把 max_err 压到 ≤1°
3. **夹爪余量评估**：实测夹爪最大张度，确认是否能包容 16mm 误差下仍可靠夹取 3cm 正方体

### 5.4 问题 3：最终回零等待时间较长

**现象**：step 11 `safe_return_home` 中 `sync_send_angles(HOME_ANGLES, 15, timeout=20s)`，从 home_ready（arm_max_diff≈34°）回直立零位耗时偏长。

**根因**：回零速度硬编码为 15（低速安全），加上 20s 超时窗口。实际上从 ~34° 偏差回到直立，物理运动时间约 6~8s。

**建议**：回零速度从 15 提升到 20~25，超时可从 20s 缩至 12s。因 home_ready 已通过 arm_max_diff≤45 安全门，回零路径短且无障碍，无需保守低速。

### 5.5 问题 4：示教点位复用

**现象**：每次运行都必须重新执行完整的五点手动示教，包括 home_ready。目前已积累了多组经过验证的示教点（run-10 home_ready [7.29,-43.06,4.57,...]、run-11 Run A [4.92,-32.34,-0.17,...]、run-11 Run B [-0.79,-30.84,-4.3,...] 等），均可 0 轮人工扶正。

**建议**：
1. **增加预设点位表**：在脚本中增加一个硬编码的示教点储存区，通过命令行参数 `--preset N` 直接加载已验证的点，跳过手动示教阶段
2. **点位配置文件**：将示教点保存为 JSON/YAML 文件，每次运行可选加载或重新示教
3. **快速基线模式**：保持 1~2 组"保底"示教点（pick_hover/pick/drop_hover/drop/home_ready）作为默认位置，仅当物理布局变化时才重新示教
