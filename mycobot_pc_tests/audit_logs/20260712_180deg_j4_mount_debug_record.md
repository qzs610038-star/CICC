## 2. 已确认事实

### 2.1 Step 2 的严格到位失败不是通信崩溃

`HOME -> pick_hover` 在 `164639`、`164926` 等回放中出现 `sync_send_angles()` 返回 `0`。后续探针读取到的终态高度规律一致：J4 通常比指令低约 `1.84°–2.20°`，内部正运动学坐标相对示教 `pick_hover` 约低 `6–8 mm`。此前 `get_angles()/get_coords()` 偶发 `-1` 仅表示 pymycobot 未收到有效应答，不能作为有效姿态；本次 J4 结论基于返回正常列表的多次读回。

### 2.2 下探/抬升偏差在未闭爪探针中已存在

三次 `--probe-pick`（`191421/191542/191615`）均未闭爪，但 `pick` 实际内部坐标约为 `[26.0, 216.1~216.2, 84.0~84.1]`，相对示教目标 `[23.3, 218.7, 89.9]` 的内部残差约 `6.87–6.99 mm`。抬回 `pick_hover` 后内部 Z 约为 `152.8 mm`，比示教 `160.8 mm` 低约 `8 mm`。

因此，“闭爪勾住台面导致 Step 5 抬不高”不是该系统性偏差的根因；闭爪可能增加风险，但不是最早出现的位置误差来源。

### 2.3 J4 单变量偏置方向有效，但严格到位仍失败

`test_j4_bias.py` 将 J4 指令改为 `pick_hover.J4 + offset`，以原 `pick_hover` 坐标为参考记录终态。结果如下：

| J4 偏置 | 实际 J4 / 指令 J4 | 内部三维残差 | dX / dY / dZ | 严格同步结果 |
|---:|---:|---:|---:|---|
| -2.0° | 43.50° / 45.37° | 9.47 mm | +2.9 / -2.7 / -8.6 mm | 未记录为成功 |
| -1.5° | 44.03° / 45.87° | 9.16 mm | +4.1 / -2.5 / -7.8 mm | 未记录为成功 |
| -1.0° | 44.47° / 46.37° | 7.90 mm | +2.4 / -2.2 / -7.2 mm | 未记录为成功 |
| +3.5° | 48.86° / 50.87° | 3.79 mm | +3.7 / 0.0 / -0.8 mm | `sync_send_angles = 0` |
| +4.0° | 49.30° / 51.37° | 3.71 mm | +3.7 / +0.2 / -0.2 mm | `sync_send_angles = 0` |

结论：

- 正偏置把**内部**残差明显降低，`+3.5°` 是后续机械结构稳定后可复测的候选值。
- `+3.5°` 与 `+4.0°` 仅相差 `0.08 mm`，低于当前一次读数/重复性能够区分的程度；不得宣称 `+4.0°` 更优，也不得将任一值固化进正式 CPU 点位表。
- 两次正偏置仍返回 `0`，所以它们不能作为“Step 2 已严格到位”或“可以继续下探”的证据。

## 3. 新发现：机械臂—乐高底座连接位移

用户已确认：工作台上的底座整体固定，但机械臂本体通过乐高连接到底座的结构会在臂运动时发生微小倾斜；目前不能完全取消乐高结构，只能增加连接件，仍预期有位移。

这是当前最高优先级的外部误差源，原因如下：

1. `get_coords()` 是由机械臂关节读数计算出的、相对机械臂自身底座的坐标，不测量底座相对工作台/工件的实际倾斜。
2. 因此，即使日志显示 3.7 mm 的内部残差，夹爪相对工件的真实偏移仍可能更大；该偏移不会被当前脚本发现。
3. 以约 280 mm 臂展估算，底座姿态偏 `0.5°` 即可带来约 `2.4 mm` 的末端横向漂移，已接近抓取小方块的有效余量。

J4 的约 2°指令—读回静差依然是独立事实；底座倾斜可能改变其负载，但不能单独解释“J4 读回始终低于指令”。当前根因是**J4 末段静差与底座连接柔性叠加**，尚不能分离出各自对真实抓取误差的份额。

## 4. 脚本证据边界

`test_j4_bias.py` 第 56–58 行使用 `ignore_error_exit=True`：严格同步失败后仍采集终态数据。其用途是诊断，而不是动作成功判定；脚本显示“实验完成”不等同于 `pick_hover` 已按严格门到位。

该脚本也只读取一次 `get_angles()` 和 `get_coords()`，且没有外部测量基准。因此它只可用于比较候选偏置方向，不能认证真实抓取位置或乐高结构刚性。

## 6. 乐高结构的风险缓解与复测门

在不能取消乐高结构时，至少采用多点、分离距离尽可能大的冗余连接与三角支撑，避免单一立柱或单一摩擦面承受俯仰力矩；不得依靠胶带、软垫或夹压机械臂外壳来“固定”。这只是风险缓解，不能把有可见位移的结构判为刚性固定。

加固完成后的首个验证必须是外部基准检查：在机械臂底座和固定平台上设置跨界对齐标线，采用相同的轻微手动载荷观察连接处相对位移。若可见滑移或可量测位移超过 0.5 mm，则保持真实抓放和板上真实臂 NO-GO。通过后才可在人员、净空和物理断电方式均已确认的前提下，以 `+3.5°` 候选值进行两次**仅悬停、不开夹爪、不下探**复测；验收依据为外部固定标记下的重复位置，而不是仅看 `get_coords()`。

任何重新加固、重新安装或底座高度/姿态变化后，现有 `20260712_180deg` 预设均需重新示教或至少逐点外部复核，才可作为后续 CPU 点位表候选。

## 7. 上板推进顺序（本阶段）

1. **D1：CPU/APB 无机械臂闭环**：CPU Hello -> `board_io_validate()` 的 `REG_MAGIC` -> heartbeat -> ARM/ERROR 状态可见。现有 `board_io_validate()` 仍依赖占位 MMIO，必须由 SoC 生成真源替代后才可上板验证。
2. **D2：UART2 无机械臂回环**：确认 UART2 真源、时钟和 `1,000,000 bps, 8N1`；通过本地回环/监听器记录 100 帧、超时和溢出结果；用 `mycobot_protocol.c` 验证 `GET_ANGLES` 请求帧和分段/坏帧解析。
3. **停止点**：D1/D2 任一项缺少 `soc.h`、地址/IRQ、电平或原始记录时，不接机械臂线；转回 F1 的 CPU/视频保底。
4. **D3 以后**：结构加固验收、T0 电平/线序/共地/急停证据和 Codex Review Packet全部具备前，不进行真实臂只读；不发送 `SEND_ANGLES`、夹爪、上使能或释放扭矩帧。
