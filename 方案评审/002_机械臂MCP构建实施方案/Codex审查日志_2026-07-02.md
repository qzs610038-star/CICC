## 主要问题

### P0-1：串口与 myCobot 首批只读工具仍未实现

证据文件：

- `final_project/tools/mcp/fpga_robot_mcp/src/fpga_robot_mcp/serial_probe.py`
- `final_project/tools/mcp/fpga_robot_mcp/src/fpga_robot_mcp/mycobot_tools.py`
- `final_project/tools/mcp/fpga_robot_mcp/src/fpga_robot_mcp/board_tools.py`

实测结果：

```text
board_list_uart_candidates -> not_implemented
mycobot280_check_env       -> not_implemented
mycobot280_list_ports      -> not_implemented
```

影响：

- 现在 MCP 无法真实枚举 COM 口。
- 无法区分 CP210x、蓝牙 COM、JTAG UART、Type-C UART。
- 无法判断 myCobot 280 是否已连接。
- `fpga_robot_status()` 中的串口和 myCobot 部分只能嵌入 `not_implemented`，不能作为环境判断依据。

建议 Claude 优先修：

1. 实现 `serial_probe.classify_port()`。
2. 实现 `serial_probe.list_ports()`。
3. 实现 `serial_probe.get_uart_summary()`。
4. 实现 `mycobot_tools.check_env()`，仅做 Python 版本、依赖和串口可见性检查，不连接机械臂。
5. 实现 `mycobot_tools.list_ports()`，调用 `serial_probe.list_ports()` 并筛选 CP210x 候选。
6. 实现 `board_tools.list_uart_candidates()`，过滤蓝牙端口并分组。

影响：

- 测试中加入断言：`get_recent_audit()` 不包含完整 token。

### P1-2：`mycobot280_stop` 未经过安全门控但底层是硬件命令

证据文件：

- `final_project/tools/mcp/fpga_robot_mcp/src/fpga_robot_mcp/server.py`
- `final_project/tools/mcp/fpga_robot_mcp/src/fpga_robot_mcp/mycobot_tools.py`

当前设计：

```python
def mycobot280_stop(...):
    return _safe_call(mycobot_tools.stop_motion, port, baudrate)
```

说明：

- 停止命令作为安全动作可以允许高优先级调用，这是合理的。
- 但它仍然是实际串口硬件命令，不应完全按普通只读工具处理。

建议 Claude 修正：

- 增加独立安全级别或明确规则，例如 `SafetyLevel.SAFETY_ACTION`。
- 允许 stop 在 `allow_hardware_actions=false` 时执行，但必须记录 audit，且只能调用白名单停止/释放命令。
- 底层实现前先保持 `not_implemented` 是安全的；实现时必须补测试。
