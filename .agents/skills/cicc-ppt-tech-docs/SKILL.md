# 集创赛 PPT 与技术文档撰写

## 先确定事实边界

1. 从仓库根目录读取 AGENTS.md、CURRENT_STATE.md 和与任务直接相关的官方细则、源码、接口契约、构建或板级证据。
2. 将本机参考资料库 CICC技术文档与PPT收集整理/ 仅视为结构、表达和视觉组织参考；不要将其案例、指标或外部链接当作当前项目事实。
3. 先打开 ../../../ppt_doc_outlines/REFERENCE_LIBRARY_INDEX.md，再按快速选用定位所需材料。资料库缺失时，继续基于项目权威来源工作，并在交付物中标注该限制。

## 按交付物执行

### 答辩 PPT 或演讲稿

1. 明确时长、受众、评分约束和每页唯一结论。
2. 为每页建立“要说什么—项目事实来源—状态标签—图表来源”四项记录。
3. 将方案、已验证结果、当前阻塞和后续计划分开陈述；不要用效果图、架构图或历史案例暗示未完成能力。
4. 制作实际 .pptx 时，同时使用当前环境可用的演示文稿制作能力；本 skill 负责证据边界和材料路由。

### 技术文档、章节大纲或摘要

1. 若当前 checkout 含 ../../../ppt_doc_outlines/technical_document_outline.md，先复核其引用后再复用；否则依据官方写作要求与资料库索引构建章节，而不是无依据地复制参考案例的目录。
2. 对每个技术主张给出直接项目来源：官方规则、当前状态、真实代码/配置、构建日志、Host 测试或板级证据。
3. 制作实际 .docx 时，同时使用当前环境可用的文档制作能力；本 skill 负责来源选择、写作结构和事实校验。

### 资料库索引或引用维护

1. 只在 ppt_doc_outlines/ 内创建或更新索引、草稿和相对链接。
2. 使用 ../CICC技术文档与PPT收集整理/... 形式链接本机资料；禁止新增机器相关 file:/// 绝对路径。
3. 不复制、移动、重命名或提交 CICC技术文档与PPT收集整理/ 及其图片、模板和 Office 临时文件。

## 使用统一状态语言

| 标签 | 可使用的证据 | 禁止外推 |
| --- | --- | --- |
| 已验证 | 匹配批次的执行日志、测试结果或板级现象 | 不得扩大到未测接口或另一批硬件输入。 |
| Host 已验证 | Host 测试或仿真 | 不得写成 SoC、UART、视频或机械臂板级通过。 |
| 设计已冻结 / 待实现 | 已批准契约或计划 | 不得写成已实现。 |
| 历史证据 | 旧批次日志或历史工程 | 不得写成当前基线。 |
| 计划 / 待验证 | 未来步骤或假设 | 不得用肯定式结果措辞。 |

更详细的选源、引用和交付核对规则见 references/authoring-evidence-rules.md。

## 完成前检查

1. 对赛题、分数、接口、状态、性能和动作安全主张逐项回链到权威项目来源。
2. 确认每个参考库链接仍使用相对路径，并运行：

   ```powershell
   & .\.agents\skills\cicc-ppt-tech-docs\scripts\validate_reference_links.ps1
   ```

3. 报告已验证事实、未验证项、使用的参考材料以及任何本机资料库缺失情况。
