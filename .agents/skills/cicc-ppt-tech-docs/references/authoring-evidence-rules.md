# PPT 与技术文档：选源和证据规则

## 事实来源优先级

| 要写的内容 | 必须优先使用 | 本机资料库可提供 |
| --- | --- | --- |
| 比赛任务、评分、时限和现场流程 | 官方比赛细则 | 结构和答辩表达参考。 |
| 当前 Gate、阻塞、下一步和禁止项 | CURRENT_STATE.md | 不可替代。 |
| 模块存在、接口、参数和实现细节 | 当前源码、XML、SDC、生成物和契约 | 图表或章节组织参考。 |
| 构建、测试、性能和板级结论 | 同批次命令、日志、制品和板上现象 | 验证矩阵的呈现方式。 |
| 设计动机、技术背景和叙事 | 上述事实加已标注的合理推断 | 优秀案例、写作规范和外部资料入口。 |

将 ppt_doc_outlines/REFERENCE_LIBRARY_INDEX.md 作为资料库的唯一导航入口。不要在本文件重复维护其文件清单。

## 推荐的主张记录格式

在写作前，为每个关键主张维护最小记录；可写在草稿表格、PPT 备注或 Review Packet 中：

| 字段 | 示例 |
| --- | --- |
| 主张 | “分类器 Host 测试已执行” |
| 状态标签 | Host 已验证 |
| 项目证据 | 测试脚本、日志和 CURRENT_STATE.md 中的相同批次状态 |
| 参考材料 | P11 的图表布局（可选） |
| 不能声称 | “已完成板级闭环” |

## 写作规则

1. 将“项目事实来源”和“结构/表达参考”分成不同注释或引用字段。
2. 引用本机资料库时使用相对路径；引用项目文件时优先使用从当前 Markdown 文件可解析的相对路径。
3. 资料库或模板无法在队友机器上打开时，保留相对链接并标记为“本机参考资料库”；不要改写为 D:\... 或 file:///...。
4. 未找到直接证据时，删去肯定式结论，或改写为 计划、待验证、历史证据 或明确的假设。
5. 遇到机械臂、接线、UART2、bitstream、XML/SDC、接口冻结或板级测试主张时，先遵循 AGENTS.md 的安全 Gate；文档撰写不授权硬件动作。

## 交付物自检

- PPT：每页只有一个核心结论，讲述时间可加总，图表来源清楚，页中结论有状态标签。
- 技术文档：目录反映实际系统边界，设计与验证分节，结果表只使用可复核数据，未验证项显式保留。
- 索引：不跟踪资料库原件，链接可解析，模板与 Office 临时锁文件不被当作内容来源。
